# FAQ 등록·수정·조회 및 초기 데이터

관련 이슈: [S15P31D109-21](https://ssafy.atlassian.net/browse/S15P31D109-21).

FAQ 원본은 기존 `faq_entries`에 저장한다. 모든 ACTIVE 관리자 역할(`OPERATOR`, `SUPERVISOR`, `SYSTEM_ADMIN`)이 등록·수정·조회할 수 있고, AI는 별도 조회 API로 최신 원본만 가져간다. 활성·비활성·삭제·분류·태그는 이번 범위에 포함하지 않는다. 새 컬럼·테이블·마이그레이션은 없다.

## API 목록

| 호출 | 권한 | 결과 |
| --- | --- | --- |
| `GET /api/faqs` | 관리자 세션 | 질문·답변 검색 및 목록 |
| `GET /api/faqs/{id}` | 관리자 세션 | 관리자용 상세 |
| `POST /api/faqs` | 관리자 세션 + 허용 Origin | 204, Location에 상세 경로 |
| `PATCH /api/faqs/{id}` | 관리자 세션 + 허용 Origin | 204, 전달한 질문·답변만 변경 |
| `GET /api/ai/faqs` | AI MVP 조회 | 관리자 식별자를 제외한 목록 |
| `GET /api/ai/faqs/{id}` | AI MVP 조회 | 관리자 식별자를 제외한 최신 상세 |

관리자 세션은 로그인 시 발급한 `dva_session` 쿠키다. AI 서비스 인증은 기존 MVP 합의대로 생략하며, FAQ 조회에는 통화 헤더가 필요하지 않다. 관리자 쿠키가 전달되면 정상 세션 검사를 수행하고 잘못된 쿠키를 익명 요청으로 전환하지 않는다. AI 조회 메서드만 인증 생략 대상으로 명시하며 관리자 쓰기에는 적용하지 않는다.

## 관리자 등록·수정

```http
POST /api/faqs
Origin: http://localhost:5173
Cookie: dva_session=<관리자 로그인 쿠키>
Content-Type: application/json
```

```json
{
  "question": "택배 접수는 어떻게 하나요?",
  "answer": "전화 상담으로 접수를 요청할 수 있습니다.\n\n- 출발지와 도착지를 알려주세요."
}
```

- 등록은 질문과 답변 모두 필수다. 공백만 있는 문자열·null·NUL 문자는 거부한다. 질문은 최대 1,000자, 답변은 최대 20,000자다.
- `PATCH /api/faqs/123`에 `{ "answer": "수정된 답변" }`만 보내면 질문은 유지한다. 질문·답변 중 하나 이상 필요하며 버전 비교는 하지 않는다. 동시에 서로 다른 필드를 바꿔도 생략한 필드는 덮어쓰지 않는다.
- `updatedByAdminUserSeq`는 서버가 로그인 계정에서 결정한다. 질문·답변 이외의 본문 필드는 거부하며 `isEnabled`, `expectedVersion`, 요청 키 등은 본문으로 받지 않는다.
- 별도 `Idempotency-Key`를 요구하지 않는다. 기존 DB에 질문 고유 제약은 없으며 같은 질문의 별도 등록을 자동으로 합치지 않는다. FE는 등록 중 버튼 중복 클릭을 막는다.
- 성공 응답은 본문 없는 204다. 등록의 `Location: /api/faqs/123`으로 상세를 조회할 수 있다. 생성·수정과 성공 감사 기록은 같은 트랜잭션으로 저장한다. 감사 저장 실패 시 FAQ 변경도 롤백한다.
- 답변의 문단·목록·Markdown 표는 문자열 그대로 보존한다. FE가 Markdown을 표시할 때는 HTML을 정제해 렌더링한다.

## 목록·상세 및 AI 제공

두 목록 모두 `q`(선택, 최대 200자), `limit`(기본 20, 1~100), `offset`(기본 0)을 지원한다. `q`는 앞뒤 공백과 유니코드 표기를 정규화하고 질문·답변을 대소문자 구분 없이 부분 검색한다. `%`·`_`는 일반 문자다. `faqEntrySeq` 오름차순으로 정렬하므로 수정 시 목록 위치가 바뀌지 않는다.

```json
{
  "data": [
    {
      "faqEntrySeq": 123,
      "question": "택배 접수는 어떻게 하나요?",
      "answer": "전화 상담으로 접수를 요청할 수 있습니다.",
      "updatedAt": "2026-10-28T01:00:00.000Z"
    }
  ],
  "hasNext": false
}
```

위 예시는 AI 목록 응답이다. 관리자 목록·상세에는 `createdAt`, `updatedByAdminUserSeq`가 추가된다. 단건 응답은 `{data: FAQ, meta: {requestId}}`이고 목록은 `{data: FAQ[], hasNext}`다. 모든 응답은 `Cache-Control: no-store`다.

AI는 목록을 `hasNext=false`까지 순회해 원본을 가져가고 필요하면 ID로 최신 내용을 다시 조회한다. 각 조회는 커밋된 최신 DB 값을 반환한다. 여러 페이지 전체를 하나의 고정 시점으로 보장하지 않으며 API 호출만으로 AI의 임베딩·검색 인덱스를 갱신하지 않는다. 읽어 간 원본을 검색 데이터에 반영하는 것은 AI 파트 책임이다. 별도 백엔드→AI 전송·동기화 작업은 추가하지 않는다.

## 초기 FAQ 32건 등록

사용자가 제공한 `delivery_faq.md`에서 질문과 답변 32건을 [초기 데이터](../../backend/data/delivery-faq.json)로 추출했다. `[일반]`, `[디포스트]`, `[디버]`, `[프로젝트]`, `[기업 추가 답변]` 출처 표기와 문서 소개·출처 설명·분류 제목을 제거하고 답변의 여러 문단·목록·표는 유지했다. 파일에는 `question`, `answer`만 있다.

최초 등록 명령은 **FAQ 테이블이 비어 있을 때만** 전체 자료를 저장한다. ACTIVE 관리자 로그인 ID를 지정하면 실제 계정 번호를 찾아 `updated_by_admin_user_seq`와 감사 기록에 남긴다. 계정을 임의로 생성하거나 고정 관리자 번호를 사용하지 않는다.

로컬에서 DB 연결 환경변수(`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`)를 전달한 상태로:

```sh
npm run bootstrap:faq -- operator01
```

배포된 백엔드 컨테이너에서는 이미 빌드된 명령을 한 번 실행한다:

```sh
node dist/faqs/bootstrap-faq.js operator01
```

`operator01`은 실제 ACTIVE 관리자 로그인 ID로 바꾼다. 명령은 환경변수로 연결하며 `.env` 파일을 읽지 않는다. 운영 이미지에도 컴파일된 명령과 JSON을 포함하므로 별도 원본 Markdown 파일이 필요하지 않다.

- FAQ가 한 건이라도 있으면 전체 초기 등록을 건너뛴다. 재실행·앱 재시작으로 기존 내용을 덮어쓰거나 빠진 항목을 다시 추가하지 않는다. 서버 시작 시 자동 실행하지 않는다.
- 전체 자료·관리자 확인 후 한 트랜잭션으로 질문·답변과 감사 기록을 저장한다. 오류가 나면 부분 등록하지 않는다.
- 동시 초기 등록과 관리자 쓰기는 테이블 잠금으로 직렬화하며, 먼저 등록된 데이터가 있으면 초기 등록을 건너뛴다. 별도 초기화 기록 테이블·요청 키는 만들지 않는다.
- FAQ 문구는 제공 자료를 유지한다. 자료의 지점별 요금표·접수 시간·취소 안내가 실제 프로젝트 접수 로직과 일치하는지는 운영 콘텐츠 검토 대상이다. 예를 들어 현재 접수 API의 상세별 3,500원 정책을 이 작업에서 변경하지 않는다.

## 오류·검증

| HTTP / code | 의미 |
| --- | --- |
| 400 / `INVALID_REQUEST` | 본문·번호·검색·페이지 조건 또는 추가 필드 오류 |
| 401 / `UNAUTHORIZED` | 관리자 세션 없음·만료·비활성 |
| 403 / `FORBIDDEN` | 관리자 권한·Origin 오류 |
| 404 / `NOT_FOUND` | FAQ 또는 요청 경로 없음 |
| 500 / `INTERNAL_ERROR` | DB·감사 저장 실패. 빈 검색 결과나 성공으로 응답하지 않음 |

Swagger는 `FAQs`와 `AI FAQs` 태그로 분리한다. `node scripts/check.cjs`는 실제 임시 PostgreSQL·NestJS HTTP·운영 Docker 이미지·Nginx를 통해 관리자 권한, 최신 조회, 검색·페이지, 동시 수정, 감사 롤백, 초기 등록·재실행·경쟁·실패 롤백, 기존 API 회귀를 검증한다. AI 검색 인덱스 연결과 실제 운영 데이터 등록·배포는 이 검증에 포함하지 않는다.
