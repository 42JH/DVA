# 백엔드 최적화 작업 기록

- 기준: `develop-backend` / `f20206a3947dcf6467c9a1674aee76d280940252`
- 브랜치: `refactor/backend-optimization`
- API URL·요청·응답·인증·오류 코드·정확한 total_count·일괄 등록의 원자성을 유지한다.
- 각 작업은 계획 → 구현 → 검증 → 채택 또는 복구 순으로 진행하고 독립 커밋으로 기록한다.
- 실제 서비스 DB와 배포 작업은 이 기록의 로컬 적용·격리 검증과 구분한다.

## 단계와 채택 기준

| 순서 | 계획 | 검증 및 채택 기준 |
|---|---|---|
| 1 | CI 누락 경로 보완, 보수적인 변경 범위 판정, 중복 컴파일 제거 | 누락된 경로·삭제·복수 커밋·기준 누락을 검사한다. 공통·DB·인증 변경과 배포는 전체 검증을 유지한다. Docker에서 컴파일한 결과로 동일 테스트를 실행한다. |
| 2 | 테스트 준비 중복 제거 | 역할별 불필요한 앱 생성과 표시 문구 단언을 정리한다. 보안·롤백·동시성·원본 데이터 검증은 유지하며 테스트 수와 시간을 기록한다. |
| 3 | 워커 연결 점유 단축, FAQ 순차 처리 개선, 직원·주문 상세 일괄 SQL, 유지보수 트랜잭션 단축 | 외부 I/O 중 DB 연결을 반납한다. 중복 작업·만료 후 재선점·오래된 완료를 검증한다. FAQ 순서와 실패 시 중단을 유지한다. 일괄 등록 실패 시 전체 롤백하고 기존 버전·감사·잠금 규칙을 유지한다. |
| 4 | 실제 실행 계획에 근거한 조회 인덱스 | 격리 DB의 대표 데이터와 EXPLAIN ANALYZE·BUFFERS로 비교한다. 효과 없는 인덱스는 채택하지 않는다. 검색·정렬·빈 페이지·총건수 결과가 같아야 한다. |
| 5 | 모듈 소유권 정리와 주문 책임 분리 | 다른 모듈의 Repository 직접 접근·직접 쓰기를 공개 업무 기능으로 옮긴다. 기존 공유 트랜잭션은 유지한다. 공개 API 스키마와 전체 회귀 테스트를 비교한다. |

## 변경하지 않는 설계

- Redis는 실측 필요성이 확인될 때 검토한다. 현재 PostgreSQL inbox/outbox와 멱등 처리를 유지한다.
- 모듈 내부 FK, 주문 주소·청구 명칭·결제 원본 등 이력 스냅샷은 유지한다.
- 모듈 간 FK 제거와 PIN 부서명 정규화는 소유권·삭제 정책·검색 조건 변경이 필요하므로 일괄 적용하지 않는다.
- 적용된 SQL migration은 고치지 않고 필요한 새 migration만 추가한다.
- 배송상세 수 제한, AI 알림 JSON 변경, 프론트 변경을 최적화에 포함하지 않는다.

- 변경 전 Node.js 24.22.1에서 lint·format·컴파일·단위 101개·결제 샘플 21개가 통과했다.
