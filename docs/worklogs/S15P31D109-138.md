## 1. 가변 배송비와 취소 감사

계획: 기존 상세 금액·취소 API를 재사용한다. 상세별 배송비와 주문 총액을 저장·검증하고 부분 취소 후 금액을 다시 계산한다. AI 취소 이력과 금액 변경 로그를 요청 주체에 맞춰 기록한다. 적용된 migration은 수정하지 않는다.

영향: 주문 생성·미완료 보완·수기 생성·접수 검증·조회·취소, 감사 조회, 배송 이력 제약, 관련 DTO·테스트.

검증 전 기준: 수정 전 lint·format·build 및 단위 테스트 67개 통과. 첫 sandbox 검사는 로컬 HTTP 연결 EACCES로 실패했으며 같은 검사를 정상 통신 환경에서 재실행해 통과했다.

구현: 016 migration, 상세 배송비와 총액 DTO·저장·조회·접수 검증, 미완료 보완 필드, 취소 후 합계 재계산, AI 배송 이력, 공개 가능한 금액 감사 메타데이터를 반영했다.

검증: lint·format·build와 단위 테스트 69개 통과. 임시 PostgreSQL 실제 API에서 12,000원 중 5,000원 부분 취소 → 7,000원, 원래 상세 가격 보존, AI 감사, 중복 요청의 무변경, 전체 취소 → 0원을 확인했다. 테스트 준비의 ACTIVE 누락 및 설정 로딩 순서는 fixture에서 수정했다.

DB 검증: 전체 monolith runner 통과. 스키마·이력·PBX 보존, 재실행·체크섬 변조 차단·실패 롤백·백업 복원·기존 upgrade 검증을 확인했다. 과거 스키마 비교에는 신규 total_amount 열을 명시적으로 제외하고 migration 이력 기대값을 15개로 갱신했다.

## 2. 부서와 결제 자격

계획: 기업별 부서, 구성원 부서 배정, 개인·기업 월결제 및 부서 그룹결제 설정을 추가한다. 소속과 기업이 일치하는지 DB·API에서 검증하고 고객 확인 응답에 자격을 제공한다. 기존 구성원 이관에는 실제 팀 배정이 필요하며 임의 기본 팀을 만들지 않는다.

## 3. 주문 결제와 디버 접수

계획: 주문 status를 기준으로 결제 대기·완료·디버 접수중·완료·실패를 연결한다. 개인 카드만 결제를 기다리고 월결제·그룹결제는 자격 확인 후 즉시 완료한다. 부분 취소 시 결제 요청을 교체하고 오래된 요청의 결제 완료를 차단한다. 재접수는 같은 주문에서 재결제·중복 집계 없이 처리한다.

## 4. 자동 만료·월별 집계와 상담 조회

계획: 최초 24시간 뒤 미결제 주문을 취소하고 새 KST 월을 0원으로 시작한다. 이력은 보존하며 자동 작업은 SYSTEM으로 기록한다. 상담 조회에서 연결된 주문의 결제·접수 상태를 확인한다.

## 5. 회귀 검증과 인계

계획: 전체 정적 검사·단위·통합·DB 검증을 실행하고 변경된 계약을 갱신한다. AI 연동 규격은 `docs/api/ai-order-billing-integration.md`에 별도로 작성한다. AI 경로 변경이 없는지 확인하고 MR 제목·본문·검증 결과를 준비한 뒤 생성 전에 사용자에게 보고한다.
