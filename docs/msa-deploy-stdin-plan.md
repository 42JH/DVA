MR 생성 전 최신 `319de6fb0464c059965620b2e3c364eca1041f05`를 일반 병합했다.
작업 브랜치: `fix/msa-deploy-stdin`. 수정은 msa/docs로 제한한다.

## 확인한 원인

Jenkins #42는 DB와 네 서비스 회귀를 통과한 뒤 배포에서 실패했다.
Jenkins의 서비스 목록 반복문과 upload-app.sh 안의 SSH가 표준입력을 공유했다.
첫 operations 전송 중 SSH가 목록의 나머지를 읽어 다른 서비스 전송이 생략됐다.
055 전환 준비는 order 패키지 디렉터리가 없어 서비스 중지와 DDL 적용 전에 실패했다.
복구 파일도 아직 생성되지 않아 recovery.json 오류가 후속으로 발생했다.

## 작업과 검증

1. 현재 Jenkins의 준비/적용 shell 블록을 직접 실행하는 회귀를 추가한다.
   입력을 소비하는 SSH 상대를 사용해 5개 전송·적용, 중간 실패/완료 표식 누락을 확인한다.
   수정 전 첫 서비스만 처리되는 실패를 먼저 확인한다.
2. 사용처 6곳의 SSH를 `-n`으로 분리한다. SCP 옵션과 파일 전송 프로토콜은 보존한다.
   DB 업로드·원격 실행·클러스터 상태 조회도 호출자의 입력을 소비하지 않게 검증한다.
3. Linux 배포 회귀 전체와 실제 OpenSSH 클라이언트 재현, 배포 fixture·055 전환/복구를 확인한다.
   사용자/AI API, 서비스 런타임, SQL, 검증 기준과 검사 조건은 변경하지 않는다.
4. 검증 근거·미검증 범위를 기록하고 작업 단위 커밋/푸시 뒤 develop-backend 대상 새 MR을 생성한다.
   운영 클러스터를 수동 배포하거나 실행 중/대기 빌드를 중단하지 않는다.

## DB·테스트 실행 비용 정리

사용자의 추가 지시에 따라 다음을 같은 MR의 별도 커밋으로 진행한다.

- DB·업무 회귀·이벤트·배포 회귀 각각의 성공 commit/build를 Jenkins 빌드 변수에 기록한다.
  뒤의 배포가 실패해도 이 기록은 보존하고 다음 실행에서 실제 Git 입력을 비교한다.
  없는 기록·잘못된 기록·이력 분기는 보수적으로 다시 검사한다.
- DB 검사는 migration·실행기·검증기·기준 정책 변경으로 선택한다.
  배포 대상이 남았거나 SSH 코드·DB 문서만 바뀌었다는 이유로 전체 DB 회귀를 반복하지 않는다.
  배포용 DB 패키지는 동일 입력의 기존 성공 근거와 이번 이미지 ID를 결합해 출처를 명시한다.
  실제 서버의 pending fingerprint·DDL·백업·복구 검사는 매 배포에서 유지한다.
- 업무 회귀는 배포 대상을 기준으로 확대하지 않고 각 회귀의 마지막 성공 소스와 비교한다.
  필요한 checks/production 이미지만 만들고 배포 없는 CI는 전송 패키지를 만들지 않는다.
- 기존 !371의 반복 로그인 제거 중 고정 055 원본과 입력이 동일한 helper 3개만
  MSA 소유 patch로 임시 CI 원본에 적용한다. 실제 backend checkout은 수정하지 않는다.
  API·migration·테스트 기대값은 원본 그대로 보존하고 정확한 patch 이외 변경은 거부한다.
  최초 052 전체 진단의 별도 고정 기준도 보존한다.
- 실제 Linux/Git 선택 회귀, 고정 원본 provenance·전체 기존 업무 회귀,
  DB 재사용 패키징과 단계별 시간을 검증해 효과와 남는 한계를 기록한다.
- 전체 검증에서 발견한 fixture 초기화의 PostgreSQL 교착은 공통 테스트 준비에서 해결한다.
  임시 DB에서만 관련 테이블의 잠금 경합을 제한적으로 기다리며 업무 API와 단언은 재시도하지 않는다.
  실제 PostgreSQL 경합을 강제로 재현하고 이 준비 코드를 사용하는 네 업무 회귀를 다시 검사한다.
