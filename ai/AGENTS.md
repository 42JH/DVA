# AI Voice Order Server — Agent Instructions

## 1. 프로젝트 목표

본 프로젝트는 전화 기반 물류 주문 접수 및 조회를
수행하는 AI 상담 서버이다.

기존 외부 인터페이스와 백엔드 API 계약을 유지하면서
내부 아키텍처를 처음부터 재설계한다.

핵심 목표:
- 정확한 업무 처리
- 자연스러운 한국어 음성 대화
- 낮은 응답 지연 시간
- 예외 상황에서의 안정적인 복구
- 명확한 책임 분리와 테스트 가능성

## 2. 변경 불가 조건

다음 항목은 명시적 승인 없이 변경하지 않는다.

- 기존 BE API의 경로와 HTTP 메서드
- 요청 및 응답 데이터 스키마
- 필드 이름, 자료형, 필수 여부
- 인증 및 인가 방식
- 에러 코드와 비즈니스 의미
- PBX 연동에 필요한 외부 인터페이스
- 기존 서비스와 합의된 업무 규칙

기존 구현과 문서가 충돌한다면 임의로 판단하지 않고
차이점을 보고한다.

## 3. 기술적 전제

- Python / FastAPI 기반
- GPT-Live-1 기반 실시간 음성 상담
- Responses Delegation 사용
- 별도 Address Resolver
- RAG 기반 업무 지식 검색
- 외부 BE API를 통한 주문 업무 처리

기술적 전제와 실제 코드가 다를 경우
차이를 먼저 보고하고 확인받는다.

## 4. 아키텍처 원칙

- 외부 연동, 도메인 로직, 세션 관리를 분리한다.
- 도메인 로직은 가능한 한 외부 SDK에 의존하지 않는다.
- Tool Calling의 판단과 실제 실행을 구분한다.
- 모든 외부 입력은 신뢰하지 않고 검증한다.
- 업무 상태는 LLM 컨텍스트에만 의존하지 않는다.
- 업무 오류와 시스템 오류를 구분한다.
- 불필요한 추상화와 과도한 계층화를 피한다.
- 기존 코드를 무조건 재사용하지 않는다.
- 외부 계약을 유지하면서 내부 구현은 교체할 수 있다.

## 5. 음성 모델과 백엔드의 책임

GPT-Live-1:
- 자연스러운 한국어 음성 상호작용
- 발화 및 끼어들기 처리
- 검증된 업무 결과의 고객 안내

Backend LLM:
- 업무 의도 파악
- Tool 선택
- 업무 절차에 따른 후속 판단
- 예외 발생 시 다음 행동 결정

Application:
- 업무 상태 관리
- 입력 및 출력 검증
- 실제 Tool 실행
- API 호출과 장애 복구
- 데이터 일관성과 멱등성 보장

## 6. 예외 처리 원칙

- 예상 가능한 업무 실패는 정상적인 분기로 취급한다.
- 예외 결과에는 기계 판독 가능한 상태를 포함한다.
- 검증되지 않은 정보를 확정하지 않는다.
- 주문 생성 등 부작용이 있는 작업은 안전하게 처리한다.
- 외부 API 장애를 고객의 입력 오류로 오인하지 않는다.
- 모델이 근거 없는 조회 결과를 생성하지 않도록 한다.
- 고객에게 필요한 다음 질문을 명확하게 결정한다.

## 7. Latency 원칙

- 실제 측정 없이 최적화 효과를 단정하지 않는다.
- 외부 API 호출에 타임아웃을 설정한다.
- 독립적인 읽기 작업은 병렬 실행을 검토한다.
- 비동기 처리 과정에서 이벤트 루프를 차단하지 않는다.
- 불필요한 LLM 호출을 최소화한다.
- 첫 유효 음성 응답까지의 시간을 측정한다.
- P50, P95 지연 시간을 함께 평가한다.

## 8. 작업 절차

모든 주요 작업은 다음 순서로 수행한다.

1. 관련 코드 및 계약 확인
2. 변경 영향 범위 분석
3. 구현 계획 작성
4. 사용자 승인 후 구현
5. 단위 테스트 및 계약 테스트
6. Worklog에 작업 내용 기록
7. 변경 내역을 조회하고 되돌릴 수 있게 커밋
8. 결과와 남은 위험 보고

명시적으로 구현을 요청하지 않았다면
분석과 설계만 수행한다.
각 작업이 완료될 때 작업 내역을 요약하여 worklog에 추가한다.

## 9. 금지 사항

- 확인되지 않은 API 규약을 추측하여 구현하지 않는다.
- 기존 BE 계약을 임의로 개선하거나 변경하지 않는다.
- 테스트 통과를 위해 검증 로직을 제거하지 않는다.
- 예외를 무조건 포괄적인 except로 삼키지 않는다.
- 근거 없는 성공 응답을 반환하지 않는다.
- 사용자 승인 없이 대규모 의존성을 추가하지 않는다.
- 필요 이상의 범위를 한 번에 구현하지 않는다.
- 특정 통화·문장·조건에만 맞춘 예외 처리용 땜질 패치를 하지 않는다.
  문제가 생긴 근본 원인을 찾아 공통 경로에서 한 번에 고친다.

## 10. 완료 기준

작업 완료 시 다음을 보고한다.

- 변경한 파일과 목적
- 유지한 외부 계약
- 실행한 테스트와 결과
- 확인되지 않은 사항
- 알려진 위험과 후속 작업
