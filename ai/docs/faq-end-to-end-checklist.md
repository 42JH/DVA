## 준비 순서

1. 검증 대상 BE/AI 환경과 관리자 조작 담당자를 정한다. 현재 작업 브랜치의 AI 코드를 리뷰/배포한다.
2. 검증 대상에 맞는 전용 FAQ 컬렉션/영속 상태 볼륨과 GPU를 준비한다. 기동 때 GPU 길이 검증 API가 필요하다.

4. 먼저 AI 영속 수신을 준비하고 BE 알림 전송을 활성화한다. 같은 프로세스를 여러 소비자로 실행하지 않는다.
5. 관리 소비자/검색 모드를 활성화할 때 기존32FAQ의 bootstrap/대기 초기알림과 검색 판본을 확인한다.

6. 실제 백엔드 알림이 HTTP202가 되는지, AI 큐가 APPLIED가 되는지 확인한다. 두 상태를 같은 뜻으로 쓰지 않는다.

## 검증 시나리오

검증 FAQ 질문은 `RAG 통합검증 <고유 실행번호> 보관함 이용시간`처럼 기존 FAQ와 구별한다.
관리자 세션/허용 Origin을 사용하며 임의 DB SQL 편집이나 인증 우회를 하지 않는다.

| 단계 | 관리자 요청 | 확인 |
|---|---|---|
| 추가 | POST /api/faqs | 응답Location/목록에서 실제 새ID 확보, BE알림ID/AI202/APPLIED, 검색에 오전10시~오후4시 안내 |
| 수정 | PATCH /api/faqs/{실제ID} | 오후6시로 수정, UPDATE/APPLIED, 새본문 반환/옛본문 제외 |
| 삭제 | DELETE /api/faqs + faqEntrySeqs배열 | DELETE/APPLIED, 현재·이전 버전 Qdrant0건, 검색/캐시 제거 |

등록한 검증 FAQ는 삭제까지 확인한다. 실패 시 그 ID와 마지막 상태를 남기고 무관한 FAQ는 수정하지 않는다.

준비 완료 전 FAQ를 추가해 알림 대기를 더 쌓거나 수동으로 BE 알림을 성공 처리하지 않는다.
