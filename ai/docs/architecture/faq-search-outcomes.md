# FAQ 검색 후보와 최종 응대 근거 구분

2026-11-05 사용자 승인. `fix/faq-evidence-outcome`, 기준 `develop-ai` 5a1f14c.

## 문제와 직접 확인

운영 통화 242(16:25:33 시작)를 읽기 전용으로 확인했다. 검색 6건의 후보는 각 3개였고, AI가 `FAQ 근거 있음`을 6회 보냈으며 백엔드에 그대로 저장됐다. 날씨 검색에는 이용 시간·취소·고객센터 FAQ가 반환됐다. Live는 날씨 안내 불가를 말했고 모델도 UNANSWERED로 판단했다.

미답변의 agent_ref와 인용은 실제 원문과 일치했다. 그러나 선택한 발화 시작 시각보다 최종 재검색 시작이 약 0.55초 늦어서 기존 시간 검사에서 INVALID_AGENT_QUOTE가 발생했다. 인용 텍스트 오류나 다중 발화 인용 문제로 단정했던 가설은 직접 대조 결과 원인이 아니었다. 해당 미답변은 제외되어 백엔드 미답변 기록은 0건이었다. 다른 UNKNOWN/참조 오류도 있었으며 이번 수정이 모든 검토 실패를 해결한다는 의미는 아니다.

## 변경

- FAQ_SEARCH는 검색 후보 수만 `FAQ 검색 후보 N건 반환`으로 기록한다. 예전처럼 후보 존재/answerable 값을 실제 답변 근거 판단으로 표시하지 않는다. 검색 장애는 기존 실패 코드로 남는다. 컨텍스트가 없는 구버전 입력은 `FAQ 검색 완료·응대 검토 전`이다.
- FAQ_ANSWERED는 실제 답변 및 사용 FAQ 인용을 검증한 경우만 생성하며 `FAQ 답변 근거 있음`으로 기록한다. 단순 상식 응답이나 후보 존재만으로 생성하지 않는다.
- QUESTION_UNANSWERED는 확정된 KB_NO_ANSWER이면 `FAQ 답변 근거 없음`, KB_UNAVAILABLE이면 `지식 검색 장애로 답변하지 못함`으로 기록한다. 모델의 UNKNOWN·검증 실패를 미답변으로 바꾸지 않는다.
- UNANSWERED의 발화는 해당 문의의 앞선 검색 이후여야 한다. 재검색 전에 시작한 거절 안내가 통화 끝까지 해결되지 않은 경우도 인정한다. ANSWERED는 기존처럼 마지막 관련 검색 이후의 발화여야 한다. 화자·원문 인용·질문/검색 연결 검증은 유지한다. 미답변 사유는 기존처럼 마지막 관련 검색 상태를 따른다.
- 모델 입력과 외부 API 필드는 변경하지 않았다. review version은 unanswered-v4-search-outcome이다. 검색·임베딩·RRF·리랭킹·Live·시간 제한과 임계값은 바꾸지 않는다. 추가 모델 호출 단계도 없다.

## 프론트 전달

FAQ_SEARCH는 검색 진행 기록이다. 이를 최종 답변 성공/실패로 해석하지 않는다. FAQ_ANSWERED는 근거를 확인한 응대 결과, QUESTION_UNANSWERED는 미답변 결과이며 기존 질문 번호와 reason으로 표시한다. 동일 검색을 여러 질문이 공유할 수 있으므로 단순히 시각이 가까운 결과로 모든 검색 문구를 덮지 않는다. 검토 실패/미확정은 근거 있음이나 없음으로 단정하지 않는다.

새 summaryText는 기존 이벤트 API의 자유 텍스트이며 필드 추가는 없다. 예전 `FAQ 근거 있음`을 `FAQ에서 답을 찾음`으로 바꾸는 프론트 매핑도 `FAQ 검색 후보 있음(과거 기록)`처럼 오해가 없게 변경해야 한다. 과거 확정 이벤트·Outbox 본문을 AI가 수정하거나 재전송하지 않는다. 과거 통화 242는 별도 복구 검토 대상이다.
