## 흐름

1. 종료 시 기존 전사/업무 이벤트 초안을 Outbox insights에 먼저 고정하고 별도 작업으로 전송한다. 모델 응답을 기다리지 않는다. 검토 원본은 review_jobs에 저장한다.
2. 모델 입력 각 행에 서버가 만든 명시적 ref를 제공한다. 원래 발화 ID도 보존한다. 모델은 ref를 선택하고 서버가 기존 내부 인덱스·API 발화 순번으로 변환한다.
3. 고객/AI 참조·원문·검색 연결 검사는 유지한다. 잘못된 문의는 판정에서 제외하고 미확정으로 기록한다. 잘못된 근거 인용은 해당 근거만 제외하며 검증한 근거는 유지한다. 검증 실패를 KB_UNAVAILABLE/미답변으로 만들지 않는다.
4. 원시 모델 판정과 항목별 오류를 보호된 SQLite에 보존한다. 일반 로그에는 에러 코드만 남긴다.
5. 검토 결과를 고정한 뒤 부가 FAQ/미답변 이벤트와 최종 분석을 별도 단계로 보낸다. 분석 본문은 미리 보내 덮어쓰지 않는다. 판정 누락/최종 실패면 faqAnswerCount=null이며 0이라고 단정하지 않는다.
6. 모델/API 실패가 재시도 상한에 도달해도 fallback 본문을 한 번 고정하고 분석/대시보드를 전송한다. 기본 전사·부가 기록·분석의 전송 진행 상태를 분리해 한 단계 실패가 다른 단계를 막지 않게 한다.

## 불변성과 호환

- 새로운 insights만 deferred_review 마커로 단계별 처리한다. 기존 확정 insights/READY 결과는 기존 본문·ID·배치 규칙을 유지한다. 과거 FAILED는 운영에서 자동 재처리하지 않는다.
- 새로운 insights의 고정 payload는 기본 이벤트와 분석 틀이다. 최종 분석/부가 이벤트는 이미 있는 review_jobs.prepared_json에 한 번 저장한다. 전송 후 내용 변경은 하지 않는다.
- 기본 이벤트와 추가 이벤트의 배치 진행 수를 구분한다. 기본 발화 전송 성공 이후에만 발화 참조가 필요한 FAQ 결과를 보낸다. 추가 결과 실패와 무관하게 최종 분석은 전송할 수 있다.
- 미답변 응답 번호, 이벤트 ID/순번, 분석, 실제 발생 시각을 유지한다. 409/400 등 계약 오류는 맹목적으로 재시도하지 않는다. 외부 API 계약 변경 없음.
