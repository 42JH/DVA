# 통화 종료 후 FAQ 근거 배열 전송

## 승인 범위와 계약

2026-11-05 사용자 구현 요청. 이슈 번호 없이 feature/faq-answer-evidence에서 진행한다. 기준은 origin/develop-ai e5a9dee. 기존 로컬 develop-ai·output/tmp는 보존한다.

사용자가 제공한 faq-question-examples-ai-integration.md가 배열 계약이다. 기존 이벤트 API에 FAQ_ANSWERED 한 건과 faqEntrySeqs(1~100개, 양의 int32, 중복 없음)를 보낸다. 단건 필드·questionText를 함께 보내지 않는다. 질문·답변은 이미 전송한 UTTERANCE 순번을 참조한다. 같은 응대를 FAQ별 개별 이벤트로 나누지 않는다.

초기 확인한 develop-backend 0848174에는 배열 DTO가 없었으나, 이후 최신화한 **6a141a0**에서 feature/faq-question-examples 병합을 확인했다. 단건 faqEntrySeq와 배열 faqEntrySeqs 중 하나만 허용하고 새 연동은 배열을 사용한다. DTO·입력 정규화·migration 052·첨부와 같은 연동 문서를 대조했다. 이후 운영 DB의 사례 테이블과 실행 중 백엔드의 배열 DTO를 직접 확인해 작업 브랜치의 faq_answered_enabled=true로 준비했다. 운영 AI 반영은 이 코드/설정 배포 이후다. 실제 운영 데이터 쓰기는 검증에 포함하지 않는다.

## 구현 순서

1. 기존 종료 검토의 구조화 출력에 검색 번호·청크 ID·근거 직접 인용·답변 직접 인용 목록을 추가한다. 추가 모델 호출은 만들지 않는다.
2. 실제 전달된 Top3의 청크·source_id·인용을 검증하고 backend-faq:N을 실제 FAQ 번호로 변환한다. 검색에만 노출된 근거를 자동 채택하지 않는다. 불확실하면 빈 목록을 허용한다.
3. 복합 질문은 검색을 공유할 수 있게 한다. 인덱스 범위·질문/발화·검색 전체 포함·개별 목록 중복 검사는 유지한다.
4. 질문·답변 발화 쌍별로 FAQ 번호를 합쳐 이벤트 한 건을 생성한다. FAQ 배열을 정렬/중복 제거한다. faqAnswerCount는 기존 문의별 답변 수로 유지하며 근거 수로 늘리지 않는다.
5. 이벤트 ID·순번·실제 답변 시각을 확정한 후 기존 Outbox에 저장한다. 기존 READY/전송 완료 기록을 다시 판정하거나 새 필드로 소급 갱신하지 않는다. 기존 배치 전송/재시도/대시보드 결과를 유지한다.
6. 가짜 모델·백엔드로 다중 근거, 검색 공유, 인용/번호 조작, 발화 순번, 응답 유실 및 구버전 영속 데이터 복구를 검증한다. 공개 가상 데이터로 실제 모델도 별도 평가하고 비용·지연은 종료 후 처리로 기록한다.

## 판정의 의미와 제한

Live가 스스로 밝힌 내부 선택이 아니라 종료 검토 모델이 실제 발화와 근거를 대조한 판정이다. 인용 검증은 문장 존재 여부를 확인할 뿐 의미적 정당성을 수학적으로 보증하지 않는다. FAQ 사례 화면은 계약상 고객 발화 전체를 표시하며, 한 발화의 부분 질문만 전송하는 필드는 없다. 204여도 FAQ 수정·삭제·보존 정책에 따라 사례가 화면에 남지 않을 수 있다.

## 완료한 변경

- UsedEvidence는 search_index/chunk_id/evidence_quote/answer_quote를 담는다. 모델이 FAQ 번호를 직접 만들어 보내지 않고 서버가 검증된 source_id에서 번호를 변환한다. 응답 전 검색 여부와 실제 전달된 Top3만 사용하며, 실제 API 전사에서 잘린 인용도 거절한다.
- source_id는 backend-faq:N(양의 int32)만 인정한다. 같은 FAQ의 여러 청크를 선택해도 배열에는 한 번만 포함한다. 근거가 불확실한 ANSWERED는 빈 목록을 허용하며 FAQ_ANSWERED를 보내지 않는다. 미답변·불명확 상태에 근거를 붙인 출력은 거절한다.
- 질문·답변 발화 쌍으로 이벤트를 묶는다. 같은 고객 발화의 부분 질문 둘이 같은 AI 발화로 응대됐으면 배열을 합쳐 이벤트 하나다. 별도 발화에서 다시 응대한 경우에는 문장이 같아도 별도 이벤트다. faqAnswerCount는 기존 문의별 답변 수를 유지하므로 복합 발화의 문의 둘은 2일 수 있으나 FAQ별로 늘어나지는 않는다.
- 전사 배열 인덱스를 UTTERANCE 순번으로 변환하고 실제 송신 원문·화자를 확인한다. FAQ 결과는 기존 발화 이벤트 뒤에 붙이므로 배치가 나뉘어도 먼저 또는 같은 묶음에 발화가 저장된다. 발생 시각은 답변 발화의 기록 시각이며 검토/전송 시각을 사용하지 않는다.
- 판정 버전은 unanswered-v2-faq-evidence. 기존 READY/insights는 변경하지 않는다. 새 배열 본문이 확정된 뒤 전송 스위치를 끄면 본문에서 필드를 제거하지 않고 보류한다. 미답변·분석·대시보드 전송 경로는 유지한다.
