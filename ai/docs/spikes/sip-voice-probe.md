# 서버 안내 음성 제어 실험

## 결과를 읽는 기준

- `session.commentary.appended`는 안내가 모델에 전달됐다는 표시다. 모델의 실제 발화, 전화로 전달된 음성, 상대방이 들은 소리는 각각 따로 확인한다. `commentary`는 문장을 바꾸거나 덧붙일 수 있다. [OpenAI GPT-Live 세션 가이드](https://developers.openai.com/api/docs/guides/live-conversations)
- 준비된 오디오 클립은 `session.output_audio.fixture.play`로 재생할 수 있다. 이 API는 클립 재생 중 고객 음성을 모델에 전달하지 않으며 나중에 다시 넣지도 않는다. `fixture.played`는 서버 믹서의 완료를 알리며, 수화기의 마지막 소리와는 시각 차이가 날 수 있다. [OpenAI sideband 이벤트 명세](https://developers.openai.com/api/reference/resources/live/sideband-websocket)
- SIP 통화에서는 전사와 반사된 오디오의 시각을 보조 자료로 쓰고, 안내 횟수와 끼어들기 성공은 실제 수화기에서 들은 결과로 기록한다. [OpenAI SIP 가이드](https://developers.openai.com/api/docs/guides/voice-sip?voice-api=live)

## 테스트 회선에서 실행

서명된 수신 웹훅을 시험용 OpenAI 프로젝트와 SIP 경로에 연결한다. 테스트 프로젝트의 `OPENAI_API_KEY`, `OPENAI_WEBHOOK_SECRET`, 시험 발신 번호 `SIP_PROBE_CALLER`를 환경에 설정한다. 발신 번호 검사는 테스트 전화 선별용이며, 웹훅의 요청 검증은 기존 서명 검증기를 사용한다.

```sh
cd ai
uv run --env-file <테스트-환경-파일> python -m call_analysis.sip_voice_probe
```

서버는 `127.0.0.1:8765`에서 시작한다. 테스트용 HTTPS 입구에서 `/lab/webhooks/openai/sip-voice`만 연결한다. 시험 프로세스에는 고객·주문·기록 도구가 없다. 한 번에 한 건을 최대 90초 받는다. 클립 재생은 `--fixture <wav>`로 24 kHz 모노 PCM16 WAV 파일을 제공하면 사용할 수 있다.

| 동작 | 수화기에서 확인 |
| --- | --- |
| 접속 후 잠시 기다린 뒤 가상 이름이나 주소를 말한다 | 서버 질문을 보내기 전에 Live가 새 접수 질문을 만들거나 기록됐다고 말하는가 |
| 키패드 `1` | 세션 전체 안내로 받는 분 성함 질문이 한 번만 나오는가 |
| 키패드 `4`를 누른 뒤 가상 정보를 말한다 | 다음 client 위임 ID로 질문을 보내면 한 번만 나오는가 |
| 키패드 `2`를 누르고 긴 안내의 첫 문장이 들리면 “잠깐만요, 발송지를 바꿀게요”라고 말한다 | 안내가 멈추고 고객 말이 끝까지 들어오는가 |
| 다른 시도에서 키패드 `2`로 긴 안내를 시작하고 `3`을 누른다 | 서버 지시로 안내가 어디서 멈추는가 |
| 키패드 `5`를 누르고 클립 도중 말한다 | 준비한 클립이 한 번 재생되는가, 클립 도중의 음성이 전사되는가 |

가상 정보만 사용한다. 출력은 발화 전사, 명령과 수신 확인의 ID, 반사된 오디오의 시각을 남긴다. 수화기에서 들은 질문 횟수, 예상과 다른 질문, 끼어들기 성공 여부를 함께 기록한다. 안내 일치율 95% 이상과 서버 안내 전 자체 질문 5% 이하를 볼 때 각 조건을 최소 20회씩 실행한다. 기록되지 않은 값을 기록했다고 말한 경우는 한 건도 허용하지 않는다.

## 2026-11-11 확인 범위

- 실제 GPT-Live 기본 WebSocket에서 client 모드 세션 시작, 세션 전체 안내 수신 확인, “받는 분 성함을 알려 주세요.” 한 번의 출력 전사와 출력 음성을 확인했다. 전사와 오디오가 생성된 한 번의 관측이다.
- 같은 세션에 0.5초 시험음을 보냈다. `fixture.playing`과 `fixture.played`가 명령 ID와 일치했고, 받은 PCM 스트림에 보낸 시험음 바이트가 그대로 있었다.
- 가상 한국어 음성을 넣은 두 시도에서는 서버 안내 전에 출력 질문이 없었다. 두 시도 모두 client 위임 이벤트가 관측되지 않아 실제 위임 ID에 대한 안내 발화는 확인하지 못했다. 도구에서는 가짜 이벤트로 ID가 일치하는 응답을 검증했다.
- 읽기 지시와 문장을 함께 보낸 시도에서 Live가 “다음 시험 안내만 천천히 끝까지 읽겠습니다”라고 지시를 읽었다. 보낼 내용을 실제 안내 문장으로 바꾼 다음 시도에서는 첫 문장만 출력됐고, 뒤이어 보낸 가상 고객 발화가 전사됐다. 끼어들기 뒤 남은 안내가 들리는지와 끊기는 정확한 시각은 실제 수화기에서 확인해야 한다.
- 현재 연결 가능한 전화는 운영 회선이다. SIP 수화기에서의 재생과 끼어들기, 반복 시험에 따른 비율은 미측정이다.
