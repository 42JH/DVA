# 도구(tool) 구조

## 현재 추가된 검색 도구

`search_manual(question)`은 읽기 전용 FAQ 검색이다. 주문·상담원·대화 단계를 바꾸는 사건을 만들지 않는다. 기존 디스패처의 strict 인수/단계 검증을 거치고 raw Top3와 구간별 시간을 반환한다. client 모드(보류)는 `config/live.toml`의 `[backend.tools]`에서 도구 이름을 채우며, 결과를 Live에 직접 보낸다. 아래 Responses 결과 반환 설명은 복귀 모드에만 해당한다.

도구는 늘어날 것이므로, **도구 하나를 추가할 때 파일 하나만 만들면** 되게 한다.

- 모든 도구는 `app/tools/` 디렉토리에 둔다. 파일 하나에 도구 하나(가까운 도구 몇 개를 묶어도 되지만 파일 이름이 기능을 드러내게). 공용 부품(기반 클래스, 레지스트리, 전화번호 정규화 등)은 `app/tools/_base.py`처럼 `_`로 시작하는 파일에 둔다.
- 도구 하나 = **이름 · 설명 · 인수 모델(pydantic) · async 실행 함수**. 도구는 자기가 어느 단계에서 쓰이는지 모른다(허용 여부는 단계 쪽이 선언, `spec/flow.md`). 실행 함수는 `(ctx, args) -> 결과`이며, 상태를 바꾸는 일이 있었으면 단계를 직접 바꾸지 않고 이름 있는 사건(예: `order.submitted`)을 낸다. `ctx`는 자기 통화의 컨텍스트(통화 상태, 임시 주문, 발신번호, 백엔드 API, 서버 설정)다. 전역 상태에 손대지 않는다.
- **자동 등록**: 서버 시작 시 `app/tools/` 안의 모듈을 모두 import해 레지스트리에 모은다(데코레이터 등록 등). 이름이 겹치면 기동 실패. 도구 목록을 손으로 적는 곳은 `config/live.toml`의 `delegation.responses.tools`뿐이며, 이름만 적으면 레지스트리에서 설명·strict JSON 스키마를 채운다. 설정에 없는 도구는 모델이 쓸 수 없다.
- **실행 파이프라인은 한 곳**(디스패처): 도구 찾기 → 인수 검증 → 허용 상태 확인 → 실행(시간 제한) → 결과 직렬화 → 상태 전이 반영 → 관제 기록 → `function_call_output` + `response.create`. 개별 도구는 이 과정을 다시 구현하지 않는다. 없는 도구·검증 실패·허용되지 않은 상태·예외·시간 초과도 모두 오류 결과로 돌려준다.
- **결과 형식 통일**: 성공 `{"ok": true, ...}` / 실패 `{"ok": false, "error": "...", "retry": "다시 확인할 것"}`. 모든 결과에 현재 통화 상태 요약(`spec/flow.md`)을 붙인다. 내부 예외 메시지·스택은 모델에 주지 않고 로그로만.
- 외부 연동(요금 API, 알림톡, 상담원 전환 등)이 생기면 도구는 그대로 두고 그 연동 모듈만 바꾼다.
- **도구는 값 기록과 주문 작업에만 쓴다.** 고객 답(예/아니오·확인·저장·상담원·종료·용건)에 따른 상태 전환은 도구 왕복의 지연을 피하려고 서버가 고객 말을 직접 판별한다(`spec/flow.md`). 새 질문 단계를 만들 때 도구를 만들지 말고 단계의 `choices`·`on_answer`로 만든다.
- 고객 확인이 필요한 도구(수정·취소)는 인수에 `customer_confirmed`를 두고 도구 안에서 `require_confirmed`로 거절한다.
- 지금 도구: `get_state`, `record_order`, `lookup_orders`, `modify_order`, `cancel_order`, `search_manual`.
  - `record_order`: 택배 항목(이름·연락처·주소·규격별 수량·기타 물품·물품 가액·요청 사항)과 통화 항목(수거 희망 시각 `pickup_at`, 전화 주신 분 성함 `customer_name`)을 기록한다. 수거 시각은 시간대가 있는 미래 시각만 받아 한국 시간으로 바꾼다. 결제 방식은 도구가 아니라 고객 답 판별로 기록한다.
  - `lookup_orders`·`modify_order`·`cancel_order`는 **사용 보류**다. 백엔드에 AI가 통화 중 쓸 API가 없어서, 이 도구를 허용하는 단계(`HELD`)를 흐름에서 뺐다(`spec/backend-api.md`). 도구와 테스트는 남겨 둔다.
- 도구마다 단위 테스트 하나 이상(정상, 인수 오류, 허용되지 않은 상태). 레지스트리 테스트: 모든 도구의 스키마가 strict로 생성되는지, `live.toml`의 함수 도구 이름이 모두 레지스트리에 있는지.
