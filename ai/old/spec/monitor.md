# 관제 화면 (실시간 모니터링 전용, 임시)

- **임시 페이지**다. 나중에 지우거나 다른 화면으로 바꿀 예정이므로 꾸미는 데 공을 들이지 않는다.
- 통화 처리 코드는 관제 화면에 의존하지 않는다. 라우터와 정적 파일만 지우면 통째로 걷어낼 수 있게 분리한다.
- 임시여도 개인정보가 보이므로 인증은 생략하지 않는다. HTTP Basic, 환경변수 `MONITOR_USER`·`MONITOR_PASSWORD`. 값이 없으면 503으로 닫는다.
- 구현: `app/monitor/`(라우터 + `static/index.html`), 주소 `/monitor`, API `/monitor/api/calls`·`/monitor/api/orders`·`/monitor/api/graph`·`/monitor/api/stream`(SSE). 통화 쪽은 `app/events.py`로 알림만 던진다.

- 전화를 거는 기능은 없다. 마이크·WebRTC를 쓰지 않는다. 통화는 PBX로만 들어온다.
- 진행 중·최근 통화 목록(발신번호 일부 마스킹, 시작 시각, 상태), 선택한 통화의 받아쓰기, 고객(신규·등록, 고객번호)·수거 희망·결제 방식·통화 결과, 접수 완료해 담은 택배마다 확정 내용(항목·운임)과 운임 합계, 받는 중인 택배 카드·운임·진행 상태(백엔드에는 통화 끝에 한 번만 보낸다, `spec/backend-api.md`), 도구 호출 패널(인수 작성 중 → 실행 중 → 완료/오류, 결과·실행 시간), 오류·종료 이유 기록.
- 서버가 상태가 바뀔 때마다 SSE로 보낸다. 읽기 전용(통화에 개입하는 버튼은 아직 없음).
- 그래프 화면: 상태 그래프(`spec/flow.md`)를 단계 정의의 전이로 그린 Mermaid 그림에 선택한 통화의 지금 노드(파랑)와 거쳐 온 노드(옅은 파랑)를 칠한다. 흐름(단계 정의 모듈)별로 묶고, 어디서나 들어가는 단계(`enter_on`)는 "⟵ 어디서나", 복귀는 "⟶ 복귀"로 노드 이름 옆에만 표시한다(엣지로 그리면 너무 많다). 같은 단계에 머무는 전이(STAY)는 그리지 않는다. 그림을 열면 지금 노드로 스크롤한다. Mermaid는 CDN(jsdelivr, 버전 고정)에서 받는다. 그림에는 단계 이름·사건만 있고 개인정보는 없다.
- 접수 주문 목록 화면: 백엔드 API의 최근 접수 주문(`spec/backend-api.md` 7번).
- 프레임워크 없는 정적 HTML. 한 화면에 고정, 글자 크게, 흰 바탕 + `#2ea3ff`.
