# 주소 보정 (`app/address/`)

고객이 말한 주소(백엔드 모델이 `record_order`에 넘긴 글자)를 행안부 주소DB의 실제 도로명주소로 바로잡는다.
보정기는 `kakao_map_test`에서 옮긴 것이다(로직은 그대로, CSV 로더·카카오 검색·자체 테스트만 뺌).

## 동작

- 전제: 고객은 지역부터 말한다. 시도 → 시·군 → 구 → 도로 순으로 위 단계 안에서만 좁혀 찾고, 도로명은 발음 정규화 편집거리로, 길 번호·건물번호는 읽는 소리 거리(일/이 등)로 비교한다. 후보 도로의 실제 건물번호와 거리까지 더해 가장 가까운 실제 주소를 고른다.
- 발음 비교는 연음("인의동"→[이니동])과 첫 음절 아닌 ㅢ→ㅣ까지 같은 소리로 본다.
- 도로 이름 안의 숫자는 읽는 소리로 비교한다. 사전 쪽은 값으로 읽고("신정이펜1로"→신정이펜일로), 들은 쪽은 값·한 자리씩·하이픈 나눠 읽기 중 가장 가까운 것을 쓴다("신정 201로"→이백일·이공일, "신정 2-1로"→이일). 음성 인식이 "이펜일로"를 숫자로 받아쓴 통화(2026-10-28)에서 못 찾던 것을 고쳤다.
- 빠진 단계(이 저장소에서 추가, kakao_map_test 원본에는 아직 없음):
  - 시도를 빼고 말하면("구미시 인동9길", "강남구 테헤란로") 모든 시도에서 시·군·구부터 찾는다. 이때 시·군·구 이름은 정확히 들려야 한다(퍼지로 엉뚱한 시도의 비슷한 이름을 잡지 않게). "중구"처럼 여러 시도에 있는 이름은 모두 후보로 두고 도로명·건물번호가 실제로 있는 쪽이 이긴다. 시도를 말했으면 이 경로는 쓰지 않는다.
  - 구가 있는 시에서 구를 빼면("경기 성남시 판교역로") 그 시의 구 전부에서 찾는다(구를 말한 경우가 우선). 포항시·고양시의 시 단독 예외 행도 그 시의 구와 함께 본다.
  - 시·군·구를 빼거나("서울 테헤란로") 지역을 아예 말하지 않으면 찾지 않는다(같은 도로명이 여러 곳이라 오답 위험).
- 지번 주소("구미시 인의동 844-5", "선산읍 완전리 산 12")도 찾는다. 시군구 안의 법정동·리 이름을 같은 소리 거리로 비교하고 번지·호는 건물번호처럼 비교한다. 결과는 그 지번에 있는 건물의 도로명주소다(예: → "경상북도 구미시 인동9길 7-3"). 도로명 후보와 같은 점수표에서 경쟁한다.
- 결과(`correct()`): `confirmed`(1등이 뚜렷하고 건물번호는 들은 그대로) · `ambiguous`(후보 최대 3개) · `not_found`.
- 주소 확정(`app/tools/record_order.py` `resolve`): `record_order`가 새 주소를 기록하면서 바로 정한다(그래프 노드가 아니다. 2026-10-30 LangGraph 재구성에서 `address` 단계를 없앰). 확정·애매함은 **고객에게 다시 묻지 않고 서버가 정한다.** 못 찾음만 지우고 그 단계에서 구간 예외 문구로 한 번 다시 묻는다(2026-10-28 사용자 결정, 10-27에 되돌렸던 "되묻기"를 못 찾음에 한해 다시 넣음). 결과는 주소별로 관제 화면("주소 확정")에 보인다.
  - `confirmed` → 표준 도로명주소로 바꿔 기록(예: "서울 강남구 태헤란노 212" → "서울특별시 강남구 테헤란로 212").
  - `ambiguous` → 가장 가까운 후보(1등)로 기록.
  - `not_found` → **기록하지 않는다.** 들은 주소를 지우고 찾을 때까지 몇 번이든 다시 묻는다(A_ADDR_RETRY_SENDER/RECEIVER). 다시 물을 주소는 그 단계의 다른 빈 항목보다 먼저 묻는다(`engine.missing`이 `Call.address_retry`를 맨 앞에). 찾으면 다시 묻기 표시를 지운다. 못 찾은 주소에 붙은 상세주소도 함께 지운다(잘못 나뉜 "동 403호" 같은 값이 남지 않게). 2026-10-31: 못 찾은 주소를 두고 연락처를 먼저 묻거나, 두 번째에 들은 그대로 기록해 확정되지 않은 주소로 다음 단계로 넘어갔다.
  - 없는 주소를 비슷한 실제 주소에 억지로 맞추지 않는다: 1등이 도로명을 많이 고쳐야 하고(점수 > `CONFIRM_MAX`) 건물번호까지 바꿔야 맞으면 애매함이 아니라 `not_found`(결과의 `weak`에 그 후보). 예: "구미시 없는길 99" → 임은길 19가 아니라 못 찾음.
  - 못 찾으면 연음으로 받아쓴 길 번호를 되돌려 한 번 더 찾는다("인동 국일" → "인동 구길" = 인동9길, ㄱ받침+"일"에서 받침을 떼면 숫자 글자인 경우만, `unlink_gil`).
  - 주소록·앞 택배로 채운 주소는 보정하지 않는다(이미 실제 주소). 수정(`modify_order`, 보류)은 보정하지 않는다.
- 지번·동명·우편번호·좌표(`app/address/kakao.py`): 백엔드 접수(COMPLETE)에 주소마다 필요하다(`spec/backend-api.md`). 주소 확정 단계가 정한 주소로 카카오 로컬 "주소로 좌표 변환"(`GET https://dapi.kakao.com/v2/local/search/address.json?query=`, 헤더 `Authorization: KakaoAK {키}`)을 부른다.
  - 응답 `documents[]` 중 처음으로 값이 다 있는 것을 쓴다: 지번 = `address.address_name`, 동명 = `address.region_3depth_name`(법정동), 우편번호 = `road_address.zone_no`(5자리), 위도·경도 = `y`·`x`(문자열 → 숫자). 필드 이름은 2026-10-28 카카오 개발자 문서로 확인했다.
  - 키는 환경변수 `KAKAO_REST_API_KEY`, 시간 제한은 `[address] kakao_timeout_sec`. 키가 없거나, 못 찾거나, 오류가 나면 비워 둔다. **임의 값으로 채우지 않는다.** 비어 있는 택배가 있으면 통화 결과를 COMPLETE가 아니라 INCOMPLETE로 보낸다.
  - 주소록(PIN)에서 고른 주소는 백엔드가 준 값(좌표 포함)을 그대로 쓰고 다시 찾지 않는다.
  - 고객 주소가 카카오로 나간다(외부 전송). 로그에는 결과 유무만 남긴다.
- 조회는 SQLite(읽기 전용) 한 연결을 잠금으로 나눠 쓰고, 이벤트 루프를 막지 않게 스레드에서 돈다. 도로명은 한 번에 수~십수 ms, 지번은 100~300ms대(큰 동일수록 느림, 역삼동 약 320ms). 잠금이라 동시 통화의 보정은 줄을 선다.
- 로그에는 결과 종류만 남긴다(주소는 개인정보).

## 주소DB

- 원본: 도로명주소 개발자센터 "주소DB"(텍스트, cp949). `개선_도로명코드_전체분.txt` + `주소_<시도>.txt`.
- 변환: `uv run python -X utf8 -m app.address.db <원본 폴더> data/address.db`(1~2분, 약 600MB). 원본 중 `지번_<시도>.txt`도 쓴다. 표는 `roads`(도로명코드·도로명·시도·시군구·읍면동), `buildings`(지상/지하·본번·부번), `areas`(법정동·리), `jibun`(산여부·번지·호 → 건물). 스키마가 바뀌면 다시 만든다.
- 위치: 설정 `[address] db_path`(기본 `data/address.db`, ai/ 기준). 파일이 없으면 보정을 끄고 들은 그대로 기록한다.
- 이미지에 넣지 않는다(`.dockerignore`의 `data`, git도 무시). 컨테이너에는 `/app/data`를 읽기 전용 볼륨으로 붙인다.
  - 로컬: `ai/data/`. 배포 서버: `/home/ubuntu/dva-ai/shared/data/address.db`(릴리스마다 보내지 않고 한 번 올려 둔다. `upload.sh`가 `ADDRESS_DATA_DIR`로 지정).
- 갱신: 주소DB는 매달 나온다. 새로 변환해 같은 자리에 바꿔 넣고 컨테이너를 다시 띄운다.

## 한계

- 원래 정답을 알아낼 수 없는 오류(숫자를 다르게 들음, 다른 실제 도로로 들음)는 보정으로 막지 못한다. 그래서 마지막 확인에서 도로명·건물번호를 읽어 고객이 듣게 한다(`voice.md`). 예: "부산 해운대구 센텀로 10" → "센텀2로 10"으로 확정된다.
- 지번은 오류를 섞은 벤치가 없다(오류 없는 지번 2,000건에서 정답 86%·애매함 14%·오답 0). 한 지번에 건물이 여럿이면 애매함 → 1등으로 정해진다.
- 아파트 이름(`부가정보` 파일)으로 말한 주소는 아직 찾지 못한다.
- 애매함을 1등으로 정하므로 건물번호를 고쳐 맞춘 주소(테헤란로 112 → 111)도 그대로 들어간다. 확정보다 오답 위험이 크다.
- 정확도는 `kakao_map_test`의 합성 벤치 기준(정답 약 75%, 오답 약 3.5%)이고, 실제 통화 정확도는 아직 재지 않았다.


## 저장된 고객·기업 배송지의 좌표

2026-11-02 인계: 고객 주소의 기본좌표 1과 범위를 벗어난 좌표는 확정값으로 사용하지 않는다. 저장된 배송지에 유효한 좌표가 없으면 고객이 선택한 뒤 기존 resolve 경로(주소DB·카카오)를 적용한다. 좌표를 임의 생성하지 않으며 못 찾으면 접수 완료 조건을 통과시키지 않는다.
