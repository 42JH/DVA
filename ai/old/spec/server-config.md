# 서버 설정 (`config/server.toml`)

GPT-Live 세션 바깥의 서버 동작 변수는 전부 여기에 둔다. 코드에 숫자·문구를 박지 않는다. 시작할 때 읽고 pydantic으로 검증해 잘못되면 기동을 멈춘다. 예:

- 통화: 동시 통화 상한(OpenAI 동시 세션 한도 안쪽, 넘으면 reject 코드), reject 상태 코드(300~699), 마무리 인사 후 끊기까지 조용함 기준·최대 대기(초), 고객 무응답 종료(초)·통화 최대 길이(초), 상담원 전환 대상 SIP URI(`refer`), 웹훅 중복 제거 보관 시간
- 업무: 회사 이름(디바콜), 접수 안내 문구, 마무리 인사 문구.
- 배송비 요금표(`[fare]`): 서류·소형·중형·대형 하나당 요금(원). 백엔드는 배송비를 계산하지 않고 접수 때 검사만 하므로 AI가 이 표로 택배별 배송비와 총액을 만든다(`spec/backend-api.md` 3번). 값이 없는 규격·기타 물품이 있으면 금액을 말하지 않고 미완료로 넘긴다. 방문수거는 유인 지점 요금(서류 3,850·소형 4,950·중형 6,050·대형 7,150원, VAT 포함, 2026-10-31 결정).
- 진행 상태: `thinking.append` 최대 길이(500토큰 한도 안쪽)
- 주소 보정: 주소DB 파일 경로, 카카오 주소 검색 시간 제한(키는 환경변수 `KAKAO_REST_API_KEY`, `spec/address.md`)
- 페르소나: 통화 진입 때 대기 설정을 맞추는 최대 시간, 백엔드 재시도 간격, 결과 회신 시도 횟수, 관리자 프롬프트 최대 글자 수(토큰은 환경변수 `AI_PERSONA_TOKEN`, `spec/persona.md`)
- 백엔드 API: 고객 확인 시간 제한, 통화 결과 요청 시간 제한·다시 확인하는 총 시간·간격, 조회 개수(주소는 환경변수 `BACKEND_API_URL`, 가짜 백엔드 사용 여부는 `BACKEND_MOCK`, `spec/backend-api.md`)
- 관제: SSE keepalive 간격, 끝난 통화를 화면에 남겨 두는 시간
- 고객 답 판별: 판별 API(`engine`: decisions·responses), 모델·추론 강도(responses만), 말이 멈췄다고 볼 시간(ms), 시간 제한, 넘기는 글자 수, 선택지 최대 개수, 확인 단계 두 열쇠의 짝을 기다리는 시간(`consent_wait_sec`, 초)
- 통화 흐름(`[flow]`, `spec/LANGGRAPH_REBUILD.md` §9): 도착지 핀 매칭에서 먼저 찾을 최근 핀 개수, 확정 지연(ms, 말 멈춤 대기보다 길게 — 기동 시 검사), 늘어놓을 핀 후보 수, 검색 결과 대기(초), 다시 조회·취소 상한, 상담원 연결 가능 시간, 질문을 들었는지 볼 때 겹침 허용(ms), 듣지 않던 단계의 말 판별 대기(초). RAG Yes 점수 임계값은 `[rag] min_score`(없으면 근거 유무만)
- 로그 수준
- RAG: 컬렉션/large 모델/3072차원, BM25 비중·RRF c, Top5/Top3, 외부 HTTP/전체 검색 timeout, 재연결 대기.
- client_backend: SDK 도구 선택 timeout, 전사 대기, 히스토리 길이, 통화별 위임 상한, 맥락 조각 토큰 수와 ACK timeout.
- faq_sync: FAQ 알림 영속 접수/자동 처리 활성화, 저장 경로, 미완료 건수/본문 상한, 접수/SQLite 잠금 제한, 문서 청크 크기·겹침, 관리 전용 컬렉션·임베딩 묶음 크기, 소비자 폴링·재시도 최초/최대 간격·삭제 재점검 간격. 기존 RAG 컬렉션과 같은 이름은 거부한다. 비밀값은 환경변수 `AI_FAQ_TOKEN`. 현재 자동 처리에는 관리 색인 주입이 필요하며 기본값은 비활성이다. 계약과 구현 단계는 [FAQ 동기화](faq-sync.md).

실제 항목은 `config/server.toml`의 주석과 `app/config.py`(검증 모델)가 기준이다.

운영 FAQ 초기 이전을 완료한 환경은 `/home/ubuntu/dva-ai/shared/faq-runtime.json`에
`{"receive_enabled":true,"process_enabled":true}`를 보관할 수 있다. 비밀값이나 원문은 넣지 않는다.
`deploy/apply-faq-runtime.py`가 새 배포와 복구 대상의 `[faq_sync]` 두 항목만 적용하며 다른 설정은 유지한다.
파일이 없으면 저장소 기본값을 유지한다. 잘못된 선택이나 FAQ 미지원 릴리스는 배포를 중단한다.
처리만 켜는 조합은 금지하며 호스트 Python 3.11 이상이 필요하다.
이 배포 보완 코드를 반영하기 전에는 운영에서 직접 바꾼 값이 다음 배포에서 덮어써질 수 있다.

모델·고객에게 나가는 진행 문구(단계별 할 일, 항목 묻는 말, 진행 상태 틀, 통화 정보, 판별 지시문)는 `prompts/flow.toml`에 둔다. 도구 설명·도구 오류 문장·판별 선택지 설명(모델용)은 코드(도구·단계 정의)에 둔다.
