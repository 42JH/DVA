# RAG 기준선 결과와 결정 근거

이전 실험 원본을 보존한 2026-10-27 정리. 이번 develop-ai 통합/외부 GPU 서버에서 새로 측정한 점수가 아니다. 정확한 소수점/시간 집계는 baseline_summary.json에 있다.

## 검색과 생성은 따로 평가한다

검색은 정답 근거가 BM25/dense/RRF Top5와 리랭킹 Top3에 들어오는지(Recall@K), 첫 결과가 맞는지(Hit@1), 정답이 앞에 오는지(MRR)를 본다. 정답이 한 FAQ인 문항에서는 Hit@K와 Recall@K가 같지만 일반적으로 같은 지표는 아니다.

생성은 실제 최종 답변의 근거 충실성(Faithfulness), 기준 답변과 사실 일치/누락(FactualCorrectness), 검색 맥락의 유용한 순서(ContextPrecision), 필요한 사실 포함(ContextRecall)을 본다. Top3에 정답 문서가 있어도 잘못 읽으면 생성 점수는 낮을 수 있다.

텍스트와 Live의 백엔드가 만든 검색 질문이 다르다. Live는 전사·말바꾸기도 포함된다. 검색 개선을 모델/전달 방식 하나의 효과라고 단정할 수 없다. Live95개 도구 호출/답변 수신은 완료했으나 모두 정확한 안내라는 뜻은 아니다.

## 왜 이 파이프라인을 선택했나

1. 처음 small 통합 임베딩에서는 무인지점 소형 요금 질문에 택배사 FAQ가1위였다. 질문만 임베딩한 별도 컬렉션에서도 요금이5위, 발송완료 취소가3위, 흔들림 방지 포장이9위였다. 질문만 저장하면 실제 조건/설명/표의 의미가 빠질 수 있어 기본으로 채택하지 않았다.
2. 저장 본문4개를 재임베딩해 원래 벡터와 비교한 코사인은 약0.999932~0.999999였다. 같은 질문 벡터의 로컬 코사인·Qdrant 기본·exact 순위도34개 전체 일치했고 최대 점수 차이6.345e-08이었다. 이 사례의 원인을 단순 ID 뒤섞임/근사 탐색 오동작으로 설명할 근거가 줄었다. 전체 DB 무결성 보증은 아니다.
3. 한국어 BM25에 업무 용어를 추가하고 의미 검색과 RRF로 결합했다. 조사/어미를 제거하되 부정·수치·단위는 보존한다. 각 사용자 질문을 정답에 맞게 수작업으로 고치는 규칙은 넣지 않는다.
4. large 통합 Q+A와 검색 설명 보강을 검토했다. 설명은 검색용으로만 추가하고 원래 답변을 고치지 않았다. 질문/답변 분리·C 입력 형식·다른 리랭커 비교는 기존 브랜치/개인 로그에 보존하되 운영 선택은 원문 A + Qwen으로 좁혔다. 모델별 원시 순위 전부를 이번 코드에 묶지 않았다.
5. RRF 후보5개를 Qwen으로 재정렬해 원문3개를 전달한다. 정답1위만 고집해 단일 문서만 주면 두번째/세번째의 근거를 잃는다. Top3가 최종 정답률100%를 보장하지는 않는다.
6. Query expansion/MultiQuery는 추가 LLM 대기 때문에 제외했다. backend가 질문을 조건 보존해 검색 도구로 옮기는 작업은 여전히 한 번 존재한다.
7. 백엔드가 검색 후 다시 답변하는 단계를 없애고 Live가 직접 정리하도록 했다. 실제 지연 개선 여부는 새 서버/통화에서 측정해야 한다.

## 낮은 Relevancy를 다시 확인한 이유

Ragas0.4.3의 Relevancy는 답변에서 역으로 질문을 만들고 원 질문과 임베딩 비교한다. 기준 답변과 사실이 같은지를 직접 재는 지표가 아니다. judge gpt-4.1, temperature0, strictness3, 평가용 embedding3-small로 기준 답변95개와 다른 FAQ 답변 대조군95개를 채점했다.

- 검토한 기준 답변 평균0.521229, 다른 FAQ 대조군0.210736. 쌍별 기준 답변 우위84/95, 탐색적 AUC0.879557.
- 0.8 통과선을 대입하면 올바른 기준 답변도8/95만 통과했다. 보편적인 합격선으로 쓸 수 없었다.
- 기준 답변8개는 모두 noncommittal로 판단돼0점, 한국어 문항 중9개에 영어 역질문도 섞였다. 문구를 삭제해서 점수를 올리지 않았다.
- Relevancy는 질문 이탈 보조 지표로 유지하고 FactualCorrectness F1을 추가했다. 과거 점수는 보존했다.

## FactualCorrectness도 사람 검토가 필요하다

기존95개 실제 Live 전사와 기준 답변에 Ragas 공식 F1(beta1, atomicity/coverage low), gpt-4.1/temperature0으로 추가 채점했다. 기존 evaluation.json을 덮지 않고 evaluation_with_factual.json에 복사해 추가했다. 실패/누락0, 평균0.721368, 중앙값0.67, 만점27개, 0.5미만11개다. 평균을 정답률72.1%라고 부르지 않는다.

- faq_07_03: 수령완료 변경 요청에 접수완료까지 상담원 확인 대상으로 넓혀 말한 문제가 있다. 범위·상태 조건을 보존하도록 통합 프롬프트에 명시했다. 다만 현재 질문에 대한 수령완료 핵심 안내까지 전부 틀린 것은 아니다.
- fee_001: 무인 소형5,500원은 맞지만 VAT/지점 차이 누락으로 F1=0.5. 금액 자체 오답으로 집계하지 않는다.
- faq_12_02: 직접 포장 안내는 맞고 근거에도 있는 지점 구매 안내를 추가했지만 짧은 기준 답변에 없어0.33. 근거에 있는 추가 사실과 환각을 구분해야 한다.
- faq_11_02의 추가 보험은 다른 Top3 근거에 존재한다. faq_05_01의 주소 자동 저장도 실제 자료에 있다. 근거를 보지 않고 환각으로 표시하지 않는다. 별도 추가 개인정보/상담원 조언은 다시 검토해야 한다.

## 지연 해석

텍스트 최종 답변 평균4.552초이며 초기 backend1.941초+후속2.033초가 대부분이었다. 질문 임베딩은 평균0.197초, p95약0.281초였다. 별도 초기 smoke3.765초를 매번의 고정 대기로 일반화하지 않았다.

Live에서는 질문 끝 이후 첫 오디오 패킷 평균1.306초(맞장구 포함), 근거 전달 뒤 첫 패킷의 입력 종료 기준 평균5.788초, 마지막 출력18.859초, 관찰 종료25.081초였다. 마지막 출력은 답을 읽는 길이, 관찰 종료는6초 조용함 확인과 가상 재생까지 포함한다. 확인된 핵심 정답 발화 시작 시간으로 부를 수 없다.

Live 내부 평균 backend1.998초, 검색0.764초, 임베딩0.267초, DB0.034초, 로컬 GPU 리랭킹0.400초, 근거 ACK 전달1.671초였다. 후속 backend를 없애도 전달 시간이 생긴다. 텍스트 완료와 첫 음성은 측정 범위가 달라 직접 비교하지 않는다. GCP/RunPod의 네트워크·대기열은 아직 포함되지 않았다.

## 재현 과정에서 해결한 문제

- 너무 짧은 합성 음성이 들어간1건은 입력 검증/재생성 후 해당 실패 문항만 재개했다. 이전 시도와 원본을 보존했다.
- Windows에서 채점 체크포인트 원자적 교체 시 파일 잠금이 발생했다. 같은 계약의 임시 파일/기완료 점수를 검증해 복구했고, 확인된 winerror5/32에만 제한 재시도를 추가했다. 영구 권한 문제를 숨기지 않는다.
- 평가 SDK/Ragas 환경은 전화 SDK와 분리한다. 공식 도구/지표를 고정하고 결과/질문/원문 해시를 저장한다.

다음에는 정책 조건 보존, 기준 답변 범위 사람 검토, 새 독립 문항, 문서 밖/모호한 질문, 실제 전화에서의 도구 선택·끼어들기·장애·핵심 안내 시작 시간을 검증한다. 이번 통합 가짜 테스트와 이전95문항 실제 점수를 섞어 쓰지 않는다.
