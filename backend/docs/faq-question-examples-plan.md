# FAQ 고객 질문 사례 작업 계획

## 확정 정책

- 기존 `POST /api/ai/calls/{id}/events`의 `FAQ_ANSWERED`와 같은 통화의 고객 발화를 사용한다. 새 AI 수집 API나 질문 문자열 요청 필드를 추가하지 않는다.
- FAQ 상세 `GET /api/faqs/{id}`에 `recentQuestions`를 추가한다. 관리자 목록과 AI FAQ 원본 목록은 변경하지 않는다.
- 질문 원문을 독립적인 텍스트로 복사한다. 통화 soft delete·물리 삭제는 사례를 삭제하지 않는다.
- FAQ별 실제 응대 발생 시각(`FAQ_ANSWERED.occurredAt`)이 최신인 10개만 유지한다. 동일 시각은 사례 번호 내림차순이다.
- 같은 문장도 서로 다른 이벤트이면 별도 사례다. 같은 `eventId`의 동일 재전송은 사례를 추가하거나 보존 기간을 연장하지 않는다.
- 각 사례는 응대 발생부터 5년이 지나면 조회에서 제외하고 기존 보관 워커가 물리 삭제한다.
- FAQ 수정·soft delete는 사례 전체를 같은 트랜잭션에서 물리 삭제한다. FAQ 물리 삭제도 사례를 연쇄 삭제한다.
- FAQ 수정 전 발생한 지연 이벤트는 기존 통화 기록으로 저장하되 사례에는 추가하지 않는다. 현재 FAQ가 없거나 삭제된 경우도 동일하다.
- 원본 이벤트·발화의 보관·재전송·참조 검증, 통화 요약 `faqAnswerCount`, FAQ 수정 알림은 기존 계약을 유지한다. 과거 이벤트의 사례 소급 생성은 하지 않는다.

## 순서·변경 범위

1. migration 052 한 개: `faq_question_examples`, FAQ 수정 시 사례 정리 트리거, 최신순·5년 정리 인덱스. 통화·발화·이벤트 FK는 두지 않는다. 기존 마이그레이션은 수정하지 않는다.
2. DB 검증: `infra/database/verify.sql`과 backend DB 검증에 새 테이블·FK·트리거·052 적용·기존 데이터 보존·통화 독립성·FAQ 정리를 반영한다.
3. 이벤트 저장: 신규 FAQ 결과 참조 검증 후 같은 트랜잭션에서 스냅샷을 저장한다. FAQ 번호 오름차순으로 잠가 다중 FAQ·다중 통화 동시 수신과 FAQ 변경을 직렬화하고 저장 후 10개를 초과한 사례를 삭제한다.
4. FAQ 상세·Swagger: 기존 필드를 유지하고 `recentQuestions: {faqQuestionExampleSeq, questionText, occurredAt}[]`만 추가한다. 한 SQL 문으로 FAQ와 사례를 읽어 수정 전후 데이터가 섞이지 않게 한다.
5. 보관 워커: 통화 정리와 독립적으로 만료 사례를 기존 배치에 추가한다.
6. AI·프론트 문서를 기능별로 각각 작성하고 backend README에 연결한다. AI·프론트 코드와 운영 DB는 변경하지 않는다.

## 검증

- migration: 신규·기존 DB 전환, 재실행, 전체 롤백, 원본 FAQ·통화 이벤트 보존, 텍스트·UUID·FAQ FK 제약, FAQ 변경·삭제 정리.
- HTTP/PG: 기존 이벤트 형식·204·참조 오류·롤백·재전송 유지, 여러 FAQ에 같은 발화 사용, 같은 문장의 독립 사례, 지연 수신·10개 초과·동일 시각 정렬, 여러 앱의 동시 저장·FAQ 수정과의 잠금 순서.
- 생명주기: 통화 soft delete·물리 삭제 후 스냅샷 유지, FAQ 수정·삭제 후 전체 정리, 수정 전 지연 이벤트·전체 재전송으로 복구되지 않음, 5년 조회 제외·워커 물리 삭제.
- 노출: 관리자 상세에만 제공, 목록·AI 응답에 미노출, 원문을 HTTP·감사 로그에 복사하지 않음, Swagger 계약.
- 기존 lint·format·컴파일·단위/결제·전체 PG HTTP·운영 이미지/nginx/HTTPS 검증. 검증된 작업 단위별 커밋을 남긴다. PR 생성·원격 배포는 이번 요청에 포함하지 않는다.

## 검증 결과

- DB 단계: `infra/database/test-monolith.ps1` 통과. 30 public 테이블·27 FK·11 트리거·052 이력 확인, 기존 FAQ/이벤트 보존과 무소급 생성, 스냅샷 제약, 원본 통화 물리 삭제 후 유지, FAQ 수정/soft delete/물리 삭제 정리 및 롤백을 확인했다. 기존 백업 복원·재실행·체크섬 변조 거부·전체 원자 롤백·과거 전환 검증도 통과했다.
- API·전체 회귀 검증은 후속 기록한다. 운영 DB에는 적용하지 않았다.
