# 고객 등록 주소 필수 연동

`POST /api/customers`는 AI와 관리자 모두 이름·전화번호·주소가 필수다. 기존 Bearer 또는 관리자 세션 인증과 성공 응답은 유지한다.

```json
{
  "name": "예시 고객",
  "phoneNumber": "01012345678",
  "address": {
    "roadAddress": "서울시 예시로 1",
    "jibunAddress": "서울시 예시동 1",
    "dongName": "예시동",
    "postalCode": "01234"
  }
}
```

- 주소 생략·null·빈 객체, 필수 항목 누락·잘못된 형식은 400 INVALID_REQUEST다. 고객은 저장하지 않는다.
- 도로명·지번·동은 비어 있지 않은 문자열, 우편번호는 선행 0을 보존한 숫자 5자리 문자열이다.
- 상세주소 detailAddress는 선택이다. 생략·빈 문자열을 허용하고 null은 거절한다. 위도·경도는 보내지 않는다.
- 프론트는 주소 선택 결과의 네 필드를 담고, 상세주소 없이도 등록을 허용한다. 오류 위치는 details의 address 또는 address.필드명이다.
- AI도 완성된 주소 객체를 함께 전송한다. 주소를 아직 확보하지 못했다면 고객 단독 등록 호출을 미룬다. 현재 일반 등록 흐름은 주소를 전송하지만, 주소 없는 호출·예제·모의 테스트는 새 계약에 맞춰야 한다.

PATCH의 이름 단독 수정·주소 생략 유지·null 삭제, 과거 주소 없는 고객 조회는 유지한다. 주문의 customer 이름·전화번호형 연결과 기업 사원 등록은 기존 별도 계약이다. DB migration이나 과거 주소 자동 보완은 없다.
