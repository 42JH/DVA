# 기업 사원 목록 검색

## 계획과 범위

- feature/call-analysis-status의 9d49e03부터 4번 요구사항을 이어서 작업한다. 시작 시 작업 트리는 깨끗하다. 최신 origin/develop-backend의 추가 변경은 이번 backend/infra 변경과 겹치지 않으며 기존 커밋을 보존한다.
- GET /api/companies/{id}/members에 선택 q를 추가한다. 해당 기업의 고객 이름·소속 사번·고객 전화번호 중 하나에 검색어 전체가 부분 일치하면 반환한다. 이름·사번은 영문 대소문자를 구분하지 않고 선행 0은 그대로 비교한다. 전화번호는 숫자/하이픈 검색어에만 하이픈을 제거해 부분 비교하며 하이픈만으로 전체 전화번호가 검색되지 않도록 한다.
- q는 NFC 정규화와 앞뒤 공백 제거 후 최대 100자 문자열이다. 생략/빈 문자열/공백만 있으면 기존 목록이다. NUL·중복/배열/객체 형태·길이 초과 입력은 400이다. %, _, 역슬래시 등은 와일드카드가 아닌 문자 그대로 비교하며 SQL 값은 바인딩한다. 등록의 11자리 휴대전화 검증과 실제 로그인 등 다른 입력 계약은 변경하지 않는다.
- 기업 경로·소속 status·q를 AND로 적용하고 기존 membership 번호 내림차순과 readPage/ListResponse를 유지한다. total_count는 모든 필터 이후 페이지 적용 전 건수이며 범위를 벗어난 offset도 같은 전체 건수를 반환한다.
- status 생략 시 ACTIVE/INACTIVE를 함께 조회한다. 기존 관리자 조회의 탈퇴 고객·비활성 기업 처리도 유지한다. 삭제된 고객/소속은 제외하고 없거나 삭제된 기업은 404다. 고객/소속에 새 필드를 추가하지 않는다.
- ListMembersQueryDto·MembersRepository.list·목록 Swagger·기존 테스트와 작업 기록만 변경한다. 기존 전체 사원 검색 /api/companies/members/search와 등록/수정/삭제, 결제, 통화, DB/migration/FK/인덱스/권한/환경변수는 변경하지 않는다. 새 공통 검색 추상화나 의존성은 추가하지 않는다.
- 모든 ACTIVE 관리자 세션만 허용하는 기존 경계를 유지한다. 조회에 업무 쓰기·새 잠금·외부 호출을 추가하지 않는다. 프론트/AI 전달 명세는 후속 요구사항과 모아서 전달하며 이번에 push/MR/운영 배포는 진행하지 않는다.

1. 계획: DTO/Repository/Service/Controller 호출자, 기존 사원 목록/전체 검색/삭제/권한/페이지 계약과 테스트 실행 경로를 확인한다.

3. 검증: 이름/사번/전화번호 부분 일치, 영문 대소문자·선행 0·하이픈·NFC·특수문자, 빈/잘못된 q, 기업 격리·상태·페이지·전체 건수, 삭제/비활성/탈퇴, 접근 권한·응답 보존·업무 쓰기 없음을 확인한다. 관련 회귀와 build/lint/format 후 공식 Docker 전체 검증에서 운영 이미지/Nginx 쿼리 전달까지 확인한다.
