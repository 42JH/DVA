# 백엔드 CI 실행량·이미지 재사용 최적화

이 문서는 최초 최적화 기록이다. 후속 실행 범위 확대·테스트 준비 정리는 [테스트 정리 결과](test-cleanup-results.md)를 참고한다.

기준: develop-backend 9f6c72e. 작업: ci/backend-checks. 프론트·AI·MSA 소스, 업무 API와 DB 스키마는 변경하지 않는다.

## 작업 단위와 검증

1. **문서 전용 실행 제외**: backend/README.md와 backend/docs의 Markdown만 바뀌면 무거운 backend 검증·자동 앱 배포를 생략한다. 마지막 성공 커밋부터의 전체 diff, 삭제·이동, 기준 누락 시 전체 검증은 유지한다. 명시적 수동 배포는 기존대로 허용하고 backend 전체 검증을 강제한다. CI 선택·실제 배포 판정 shell 회귀 후 커밋한다.
2. **변경 영향에 따른 통합 테스트 선택**: FAQ·대시보드의 좁은 source/test 변경만 해당 기능과 연결 기능의 통합 테스트를 실행한다. DB·웹훅·인증 기본 검증, 전체 단위 테스트, production 이미지·Nginx/HTTPS 검증은 유지한다. 공통·인증·주문·결제·migration·의존성·모듈 배선·CI 및 미분류/혼합 변경은 전체 검증한다. 테스트 파일은 삭제하지 않으며 기본 Docker/local 전체 실행도 유지한다. 선택 경계·실제 실행 명령 회귀, 전체 Docker와 두 선택 경로를 검증한 뒤 커밋한다.
3. **검증된 운영 이미지 재사용과 npm 다운로드 캐시**: production 검증 완료 후에만 해당 릴리스 태그를 남기고 패키징이 재사용한다. 수동 패키징의 기존 build 경로, 플랫폼 확인·체크섬·DB/Nginx 포함·전송·롤백은 유지한다. npm ci는 lock 파일 기준을 유지하고 BuildKit 다운로드 캐시를 쓴다. 패키징 기본/재사용/오류 회귀와 실제 운영 이미지 검증, 최종 diff 확인 후 커밋한다.

## 실행 범위를 줄이는 기준

- 전체 테스트를 삭제하거나 기대값·인증·복구 검증을 완화하지 않는다.
- DB를 공유하며 TRUNCATE/전체 UPDATE를 사용하는 기존 통합 테스트는 순차 실행을 유지한다. DB 격리 없는 병렬화와 Jenkins/운영 서버 자원 상향은 이번 범위에서 제외한다.
- 전체 이미지 archive·SSH 전달 방식은 유지한다. 레지스트리 도입과 산출물 보관 정책 변경은 이번 범위에서 제외한다.
- 새 선택 프로필에 테스트가 누락되거나 입력 형식을 확인할 수 없으면 전체 실행 또는 명시적 실패로 처리한다.
- 변경·미변경 파일의 같은 API/DB 동작, 실패 시 배포 차단, 배포 브랜치·웹훅 검증을 유지한다.

## 측정

동일 코드에서 full/faq/dashboard의 실제 실행 건수와 통합 검증 소요 시간을 기록한다. 최초 이미지 빌드의 의존성 설치 시간과 캐시가 적용된 검증 시간을 구분한다. 로컬 결과를 실제 Jenkins 단축률로 확대하지 않는다. 운영 Jenkins 설정 변경·실제 배포는 수행하지 않는다.

## 검증 기록

- 1단계: 새 문서 경로 테스트가 기존 코드에서 실패함을 확인했다. 수정 후 CI 선택 6개, 배포 분기 shell 회귀, shell 구문 검사와 `git diff --check`가 통과했다. 문서와 코드가 섞이거나 실행 파일·이동 전 source 경로가 있으면 검증하며, 문서 수동 배포도 보호 브랜치 제한을 유지한다.
- 2단계: 전체 Docker 검증은 단위 218개와 DB/운영 861개가 통과했다. FAQ 최초 선택 실행에서 운영 주소 이력 smoke의 선행 주문 fixture 의존성이 드러나 공통 주소 이력 14개를 유지했다. 수정 후 FAQ DB/운영 258개, 대시보드 219개가 모두 통과했고 선택/Git diff 회귀 9개도 통과했다. 문서 전용 환경값이 상속된 상태의 배포 shell 회귀도 재현·수정 후 통과했다. 측정 방법과 범위는 [검증 결과](ci-optimization-results.md)에 기록한다.
- 3단계: 이미지 재사용 회귀가 기존 중복 build 경로에서 실패함을 확인한 뒤 수정했다. Linux 기본/재사용 패키징, 누락·다른 버전·다른 플랫폼 차단, 이미지·SQL 체크섬 및 SSH 회귀가 통과했다. 최종 Dockerfile로 컴파일·정적 검사·단위 218개와 DB/운영 861개를 다시 실행해 통과했다. 운영 smoke 후에만 릴리스 태그가 생성되고 임시 태그 정리 후에도 linux/amd64 이미지가 유지됨을 확인했다. CI 회귀 9개, 관측 설정과 결제 데모 인프라 검증도 통과했다.
