# 관리자 목록 검색

## 계획과 범위

- feature/call-analysis-status의 71a563d부터 5번 요구사항을 이어서 작업한다. 시작 시 작업 트리는 깨끗하다. 원격 develop-backend/develop-fe/develop-ai를 갱신했으며 기존 누적 커밋을 보존한다. 이번 제품 수정은 backend 안에서만 진행한다.
- GET /api/admins에 선택 q를 추가한다. 관리자 이름 또는 로그인 아이디에서 검색어 전체를 영문 대소문자 구분 없이 부분 비교한다. q는 NFC 정규화·앞뒤 공백 제거 후 최대 100자이며 생략/빈 문자열/공백만 있으면 기존 목록이다. 중복/배열/객체/NUL/길이 초과는 400, %, _와 따옴표 등은 바인딩한 일반 문자다.
- 기존 role/status/q를 AND로 적용하고 readPage/ListResponse의 관리자 번호 내림차순, limit/offset/hasNext와 필터 후 전체 total_count를 유지한다. 필터는 페이지 적용 전 전체 관리자에 적용한다. role/status 생략 시 기존처럼 삭제되지 않은 모든 권한·승인 대기/활성/비활성 계정을 조회한다.
- 기존 SYSTEM_ADMIN 전용 세션 권한, 삭제 계정 제외와 publicAdmin의 응답 필드를 유지한다. 비밀번호 해시·세션 정보를 응답에 추가하지 않는다. 검색만 대소문자를 구분하지 않으며 실제 로그인의 아이디 일치 규칙과 가입 승인·권한/상태·비밀번호·삭제 기능은 변경하지 않는다.
- AdminQueryDto, AdminsRepository.list, 목록 Swagger, 기존 테스트와 작업 기록만 변경한다. 기존 SELECT/Service/권한 경계를 유지하고 새 업무 쓰기·잠금·외부 호출·공통 검색 추상화·의존성·DB/migration/FK/인덱스/환경변수는 추가하지 않는다.
- 프론트/AI 전달 명세는 후속 요구사항과 모아서 전달한다. push/MR/운영 배포는 이번 범위가 아니다. 완료 보고와 함께 6번 수거 마감 시각의 현재 코드 차이와 작업 상세를 제공하되 6번 제품 코드는 수정하지 않는다.

## 작업 단위와 검증

1. 계획: DTO/Repository/Service/Controller와 호출자, 공개 응답 정제, 인증·승인·삭제·페이지 계약을 확인한다.
2. 작업: 정상 q의 기존 400 거절을 실제 HTTP 회귀로 먼저 재현한 뒤 DTO 검증·목록 검색 SQL·Swagger를 추가한다. 기존 auth/runtime 진입점에 테스트를 연결한다.
3. 검증: 이름/아이디 부분 일치·영문 대소문자·NFC, 빈/잘못된 입력·일반 특수문자, 권한/상태 조합·100명 밖 검색·정렬/페이지/전체 건수, 삭제 계정 제외·SYSTEM_ADMIN 전용·민감정보 비노출·조회 부작용 없음을 검증한다. 실제 로그인의 대소문자 구분과 기존 계정 기능도 회귀 검증한다.
4. 관련 회귀와 build/lint/format 후 공식 Docker 전체 검증의 운영 이미지/Nginx 검색까지 확인하고 결과를 기록한다. 이 작업만 feat 커밋 하나로 남기고 사용자에게 보고한다.
