# 통화 불만 판정·미완료 주문 후속 작업

기준: develop-backend `319de6fb`, 작업 브랜치 `feature/complaint-draft-follow-up`.
사용자가 MR !383 반영과 해당 코드 수정을 승인했다. 기존 테스트 정리·홈·최적화는 유지한다.

## 확정 범위와 순서

1. MR !383의 불만 판정 기능을 반영하되 최신 실행 목록에 새 테스트만 연결한다. 발화 미수집의 false 오판과 fill 재진입의 동시 처리 상한 초과를 고친다. 기존 분석·읽기 경로와 실제 guard를 회귀 검증한 뒤 커밋한다.
2. 배송 초안에 orders와 같은 시퀀스의 예약번호를 추가한다. 관리자 재개는 원본 예약번호를 이어 쓰고, AI의 여러 완성 배송은 기존처럼 한 주문으로 묶어 대표 초안 예약번호를 쓴다. 나머지 예약번호는 사용하지 않는다. 기존 미완료에도 새 번호를 부여하고 legacyOrderSeq는 원본 참조로 보존한다. 이는 사용자가 두 질문에 명시적으로 확정한 기준이다.
3. 관리자 주문 목록에 INCOMPLETE를 COLLECTING 행으로 통합한다. 전체 total_count·statusCounts.all에도 포함하고 statusGroup=COLLECTING은 초안을 조회한다. 생성 시각·검색·기간·기업·페이지 조건을 적용하며 draftSeq로 리소스를 구분한다. 실제 주문 상세·결제·보관·동시성·멱등성은 유지한다.
4. 번호·취소·통화 분석 상태·미완료 이어가기의 동작을 확인해 문서화한다.

## 1단계 검증

- 수정 전 새 회귀 두 사례를 Docker checks에서 실행해 실제로 2개가 실패함을 확인했다.
- 수정 후 `BACKEND_TEST_PROFILE=analysis node backend/scripts/check.cjs` 종료 코드 0. 단위 214·결제 데모 21·격리 DB/API 161·운영 이미지/Nginx/HTTPS 13 = 409개 통과, 실패·취소·skip 0. 컴파일·ESLint·Prettier 포함, 외부 OpenAI와 실제 S3는 호출하지 않았다.
- 신규 DB 회귀는 발화가 없는 분석을 집지 않고, 같은 통화에 발화 이벤트가 늦게 도착하면 판정하는 경로를 검증한다. 정상 판정·재시도·녹음 대기·다중 워커 경합은 기존 MR 테스트로 확인했다.
- 원래 MR의 057 migration·환경 변수·compose 전달·AI 판정 규칙을 유지한다. 운영 키 등록·migration 적용·배포·MR 병합은 실행하지 않았다.

## 2단계 검증

- 058으로 기존 초안에도 같은 orders 시퀀스의 예약번호를 부여한다. 원본 참조·주문 행·생성/보관 시각을 보존하고 재개 시 번호 소유권을 원자적으로 옮긴다.
- 최초 전체 검증은 orders의 ALWAYS IDENTITY 열에 명시 값을 넣는 경로가 실패했다. 기존 identity 제약을 바꾸지 않고 내부 INSERT에 OVERRIDING SYSTEM VALUE를 적용한 뒤 전체를 다시 실행했다.
- `BACKEND_TEST_PROFILE=full node backend/scripts/check.cjs` 종료 코드 0. 단위 214·결제 21·격리 DB/API 647·운영 이미지 13 = 895개 통과, 실패·취소·skip 0, 총 244,952ms.
- 실제 DB로 058의 기존 데이터 backfill·예약 유일성·legacy 참조·주문 미생성, 생성 재전송 번호 보존, 관리자 이어가기의 동일 번호 접수, 여러 READY 배송의 대표 번호 한 건 전환, 기존 권한·결제·동시성·롤백을 검증했다.

## 3단계 검증

- 관리자 전체 목록을 SQL UNION ALL로 통합하고 정렬·페이지 제한을 함께 적용했다. 주소 JSON 조립은 페이지 선택 후 수행하고 기존 초안 필터를 재사용한다. 실제 주문은 draftSeq=null, 초안은 draftSeq와 예약번호를 제공한다.
- all은 실제 주문 수와 미완료 수를 합산한다. COLLECTING은 초안만 조회한다. 홈의 오늘 주문 수는 기존 실제 주문 기준을 유지한다.
- 최초 전체 검증에서 기존 기업 회귀가 COLLECTING 탭에 실제 주문 fixture를 조회하던 기대와 충돌했다. 실제 주문의 기업 이동·페이지·교차 탭 검증은 전체 탭으로 유지하고, 새 혼합 목록 회귀에서 초안 전용 COLLECTING·예약번호·기간·전체 페이지를 검증했다.
- 최종 `BACKEND_TEST_PROFILE=full node backend/scripts/check.cjs` 종료 코드 0. 단위 214·결제 21·격리 DB/API 648·운영 이미지 13 = 896개 통과, 실패·취소·skip 0, 로컬 250,333ms. 이 시간은 원격 Jenkins 측정이 아니다.
- Linux Jenkins/Git 회귀 8개, 배포 trigger/deploy/package mock 3종, 셸 문법 검사와 diff 검사가 통과했다. 기존 237개 테스트 정리를 되돌리지 않고 신규 기능과 재현 오류에 필요한 22개 검증을 더했다.
- [최신 프론트 전달](parcel-draft-order-reservation.md), [누적 연동 명세](frontend-qa-api.md)를 갱신했다. 운영 배포 전에 057·058과 프론트의 draftSeq 분기가 필요하다. 기존 MR !383의 원격 브랜치는 수정하지 않았고 새 MR·병합·운영 배포는 수행하지 않았다.

## 4단계 후속 — 분석 만료·흐름·데이터 확인

- 사용자 확정의 10분 기준을 공통 통화 조회·Swagger에 적용했다. 정상 분석·최종 실패 통보가 없고 PBX 종료 후 10분이면 EXPIRED, 시간만으로 COMPLETED 처리하지 않는다. 구현 커밋은 `2e567348`이다.
- 수정 전 PENDING 잔류를 재현했다. 수정 후 analysis 409개, 최종 full 검증 대상 896개 통과(동일 빌드 레이어 재사용, DB/API 648·runtime 13 재실행), 실패·취소·skip 0, 최종 로컬 204,484ms. 기존 테스트를 보강해 전체 개수는 늘리지 않았다.
- [상세 조사 보고](analysis-expiry-and-draft-findings-20261109.md)에 이관 원본 NOT EXISTS 조건, 완료 통보+PBX 종료에 따른 미완료 확정, 고객별 다건 보관·체인별 재개, 5년 보관 기한을 정리했다.
- 자동 이어가기는 AI 설정으로 제어한다. 활성화하면 최근 미완료 한 건을 후보로 조회한다.
- 과거에 연결한 고객 행이 없으면 미답변 문의에서 고객명이 null일 수 있다. 현재 고객을 자동으로 다시 연결하지 않는다.
- 프론트·AI 상태 명세와 누적 명세를 갱신했다. 프론트의 EXPIRED 타입·‘분석 만료’ 표시가 필요하며 실제 프론트 수정·새 MR·병합·운영 배포는 수행하지 않았다.

## 5단계 — 수기 수령인 PIN

- `bf9f8a17`에서 관리자 주문 접수 준비에 수령인 개인 PIN 저장을 추가했다. 기존 고객별 pin_identity로 중복을 제외하고 원래 PIN을 유지한다. 관리자 초안 접수도 같은 경로이며 발송인 PIN·AI 코드는 변경하지 않았다.
- 공식 orders 554개 및 full 897개 검증이 통과했다. [상세 검증](manual-order-recipient-pins.md)을 따른다.

## 6단계 — 미완료 24시간·최신 확정 통화

- 사용자 확정에 따라 [24시간·최신 확정 통화 정책](incomplete-expiry-latest-call.md)을 적용했다. FAQ·조회·NO_ORDER를 포함하며 종료 및 결과 확정 이전에는 이전 건을 이어갈 수 있다. 유예는 없고 원본 시각을 유지한다.
- 최신 기준 `origin/develop-backend`의 `fc80e399`를 같은 브랜치에 일반 merge했다. 병합 충돌은 없었고 상위 MSA 변경을 수정하지 않았다.
- 신규 회귀 4개 실패를 먼저 재현했다. 최종 full 종료 코드 0: build/lint/format, 단위 214·결제 21·DB/API 653·runtime 13 = 901개, 실패·취소·skip 0, 로컬 235,739ms. Linux Jenkins/Git 8개·배포 mock 3종·셸 문법도 통과했다.
- 059는 최신 확정 통화 검색용 index 두 개를 추가한다. 미완료 원본·상태·시각을 일괄 변경하지 않으며 공통 조회/쓰기 조건으로 제외한다. 운영 READ ONLY 미리보기에서 72건 중 유효 0건이 예상됐고 실제 반영은 하지 않았다.
- 최신 develop-fe `f23693d0`에는 분석 EXPIRED 표시가 이미 구현된 것을 정적으로 확인해 전달 문서를 갱신했다. 프론트 테스트·실제 화면·운영 배포는 별도다.
- MR 범위는 1~6단계 전체다.
