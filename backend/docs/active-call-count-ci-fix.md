# 실시간 통화 수 CI 테스트 안정화

기준은 `develop-backend`의 `d94ae0f`, 작업 브랜치는 `fix/active-count-tests`다.

## 원인과 계획

- Jenkins #95는 컴파일·lint·포맷 통과 후 SSE 부하 테스트의 `reads <= 3` 조건에서 조회 4회로 실패했다.
  배포 단계는 실행되지 않았다.
- 현재 서비스는 100ms/1000ms 간격과 누적 알림 수를 사용한다. 실제 서비스의 가상 시계 재현에서
  35개를 한 번에 받으면 조회 1회, 100ms마다 8·9·9·9개를 받으면 조회 4회로 두 구독자에게 정상 전달됐다.
  Jenkins 로그에는 개별 알림 시각이 없어 #95의 정확한 도착 순서를 재현한 것은 아니다.
- 실제 DB·HTTP·SSE 통합 테스트는 첫 조회를 보류하는 동안 두 구독자가 정확히 한 조회를 공유하는지,
  해제 후 둘 다 최종 35를 받는지 확인한다.
- 100ms/1000ms 경계, 누적 10개 이상 알림의 묶기, 네 번 나뉜 35개 알림, 진행 중 조회 재사용은
  실제 서비스와 가상 시계를 사용한 단위 테스트에서 검증한다.
- 고부하 통합 테스트도 시간에 종속되는 총 조회 횟수 대신 요청이 이어지는 중의 중간값·최종값 전달을 유지한다.
  조회 주기 상한은 가상 시계에서 정확한 시점과 횟수로 검증한다.
- 단위 테스트를 기존 `test:compiled` 실행 목록에 연결하고 정규 Docker 검증과 0.5 CPU 추가 검증을 수행한다.

운영 소스·API·DTO·DB·설정·의존성·Jenkins는 변경하지 않는다. 수정은 테스트·실행 목록·이 문서에 한정한다.

## 검증 기록

- 가상 시계 단위 테스트 6개가 통과했다. 누적 알림 10개·35개, 100건/101건 경계,
  네 번 분산된 알림과 진행 중 조회 재사용을 검사한다. 실제 LISTEN 알림 handler와 두 구독자의 전달 결과를 사용한다.
- 저장소를 바꾸지 않는 임시 컨테이너에서 서비스 사본에 결함을 넣어 검증했다.
  진행 중 조회 재사용 제거, 1000ms 대기 제거, 100건 경계를 잘못 포함한 세 경우 모두 의도한 단위 테스트의 assertion이 실패했다.
- `node backend/scripts/check.cjs` 전체 817개 통과: 단위 128 + 결제 시뮬레이터 21 + PostgreSQL 통합 648 +
  실제 nginx/HTTPS 런타임 20. 실패·skip·cancelled·todo 0이며 lint·포맷·컴파일도 통과했다.
- 테스트 컨테이너만 0.5 CPU로 제한하고 별도 PostgreSQL에서 통화 수 통합 테스트 22개를 실행해 모두 통과했다.
  첫 조회 공유, 고부하 중간값 전달, heartbeat·세션 만료·종료 정리 검증을 포함한다.
- `backend/package.json` 변경은 CI에서 `shared_backend`로 분류돼 관측·결제 데모 검증도 선택한다.
  `bash -n infra/observability/deploy.sh`, `node infra/observability/test.mjs`, `node infra/payment-test/check.mjs`도 통과했다.
  관측 Bash 검사는 Windows 샌드박스의 MSYS 접근 오류 후 같은 명령을 호스트 권한에서 재실행해 통과했다.
- 전체·느린 환경 검증의 근거는 로컬 임시 로그 `dva-active-count-ci-fix-full.log`,
  `dva-active-count-ci-fix-slow.log`다. 결제 데모 인프라 로그도 별도 보관했다.

검증은 격리된 로컬 Linux Docker 기준이다. 원격 Jenkins 재검증·운영 배포는 수행하지 않았다.
운영의 집계·알림 정책과 API 계약은 그대로 유지하며 실제 AI/프론트 수동 연동은 이번 범위에 포함하지 않는다.
