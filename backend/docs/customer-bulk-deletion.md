# 관리자 고객 단건·다건 soft delete

`DELETE /api/customers`는 모든 ACTIVE 관리자 세션과 허용 Origin이 필요하다. AI 서비스 토큰·통화 헤더만으로 사용할 수 없다.

```json
{ "customerSeqs": [123, 124] }
```

배열은 서로 다른 양의 int32 ID 1~100개다. 단건은 원소 한 개로 보낸다. 빈 배열·중복·문자열·0·음수·소수·범위 초과·미지정·다른 필드는 400이다. Content-Type은 application/json이다.

고객과 미삭제 소속·개인 PIN·등록 카드·연결된 주문·통화·배송 초안을 같은 트랜잭션에서 soft delete한다. 기존 청구 합계는 유지한다. 진행 중인 통화·녹취·결제·접수가 있으면 409로 전체 요청을 롤백한다. 삭제된 고객은 고객 목록·상세·주소록·기업 구성원 목록에서 제외되며 동일 번호 재등록은 기존 탈퇴·삭제 계약을 따른다.

모든 대상이 존재하고 미삭제여야 한다. 한 건이라도 없거나 이미 삭제됐으면 404 NOT_FOUND로 전체 롤백한다. 감사 실패도 전체 롤백한다. 성공은 본문 없는 204, 대상 고객별 CUSTOMER_DELETED 성공 감사가 같은 트랜잭션에 남는다. 변경한 고객을 ID 오름차순으로 먼저 잠그고, 2초 잠금 대기 초과·데드락은 409 REQUEST_IN_PROGRESS다. 겹친 삭제를 다시 보내면 이미 삭제된 대상은 404이며 삭제 시각을 갱신하지 않는다.

067을 적용한다. 실제 폐기·익명화와 기존 삭제 고객에 대한 적용은 [보관 정책](data-retention.md)을 따른다. 삭제가 적용된 주문의 기존 결제 링크는 404를 반환한다. 프론트는 성공 후 목록·건수와 선택을 갱신한다.
