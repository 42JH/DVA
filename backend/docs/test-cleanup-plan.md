# 백엔드 테스트 정리 계획

기준: develop-backend `f7f492c1`, 작업 브랜치 `ci/backend-test-scope`.
대상은 backend 테스트·CI와 연결된 Jenkins 설정이다. 업무 소스·API·DB 스키마·프론트·AI는 변경하지 않는다.

## 1. 업무 테스트 준비의 중복 로그인 제거

- 전체 테스트 파일·분리된 하위 사례·공통 fixture와 실제 import/DB 참조를 조사한다.
- 인증 전용 테스트와 production/Nginx smoke의 실제 로그인·해시·만료·권한 검증은 유지한다.
- 공통 업무 fixture, 주문·수기 주문 fixture의 반복 로그인은 기존 페르소나/통화 이벤트 테스트처럼 임시 DB에 세션을 준비한다. HTTP 요청은 실제 인증 guard를 통과한다.
- 전체 Docker 검증으로 권한·감사·결제·트랜잭션·운영 이미지 경로를 회귀 확인한 뒤 커밋한다.

## 2. 변경 기능과 연결 기능의 DB 회귀 검증 선택

- 기존 FAQ·대시보드 한정 선택을 고객·기업/사원·PIN·주문/결제·통화/이벤트/분석·녹취·페르소나·보존/관측으로 넓힌다.
- 여러 기능 변경은 필요한 테스트의 합집합을 기존 순서로 한 번씩 실행한다. DB 공유 테스트의 병렬화는 하지 않는다.
- 인증/공통 기반·모듈 배선·의존성·migration·실행기·미분류 파일 또는 비교 기준 누락은 전체 검증한다. 수동 전체 검증도 제공한다.
- 새 테스트 파일은 분류에 등록되지 않으면 전체 실행하며, 등록된 범위의 테스트가 없어지거나 실행 명령을 해석할 수 없으면 실패한다.
- DB·웹훅·인증·운영 smoke용 주소 이력은 공통으로 유지한다. 단위 테스트와 production/Nginx/HTTPS 검증도 유지한다.
- 선택 규칙·Git diff·실제 선택 실행과 최종 전체 검증 후 커밋한다.

## 3. 결과 기록

- 삭제할 수 있는 정확한 중복과 서로 다른 계층/실패 경로를 구분한다. 숫자를 줄이기 위한 사례 삭제·기대값 완화·skip 추가는 하지 않는다.
- 프로필별 실행 목록·건수, 실제 Docker 검증 결과와 시간을 기록한다. 로컬 시간을 Jenkins 단축률로 단정하지 않는다.
- 전체 검증이 필요한 변경과 선택 실행의 제한, 서버 동시 빌드 부하 문제를 보고한다.
