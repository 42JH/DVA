# 통화 중 오집계와 PBX 정확 시각 매칭 수정

419번은 AI 종료 분석이 저장됐지만 PBX 원본 종료 시각이 없어 목록에서는 분석 완료, 상단에는 통화 중으로 집계됐다. 같은 번호의 직전 417번이 27초 앞서 시작해 기존 ±30초 매칭에서 두 후보가 생기는 경로도 확인했다. 현재 보존된 종료 수신 원본만으로 419번의 PBX 미연결 원인을 확정하지는 않는다.

진행 통화 조회는 목록과 같이 PBX 또는 AI 분석에 종료 시각이 있으면 제외한다. 분석 저장 커밋 후 기존 통화 변경 알림을 보내 SSE도 갱신한다. 원본 PBX 시각·주문 확정·분석 상태·권한·응답 형식은 바꾸지 않는다. 분석 종료와 PBX 종료가 모두 없으면 여전히 집계하며 임의 시간으로 진행 통화를 종료하지 않는다.

PBX 매칭은 같은 번호·시작 시각의 정확 일치가 있으면 그 후보를 우선한다. 정확 일치가 없으면 기존 범위 내 유일 후보를 사용한다. 정확 일치 여러 건, 범위 후보만 여러 건, 기존 PBX 시각 충돌은 계속 거절한다. 등록·즉시 수신·워커의 같은 공통 경로에 적용한다.

수정 전 실제 격리 DB/API 테스트에서 AI 종료 통화 오집계와 27초 재통화 미연결 두 사례가 실패하는 것을 확인했다. 수정 후 `BACKEND_TEST_PROFILE=full node backend/scripts/check.cjs`는 903개 통과, 실패·취소·건너뜀 0개였다. ESLint·Prettier·TypeScript 빌드, 실제 PostgreSQL 통합, 운영 이미지·Nginx·HTTPS 런타임 검증을 포함하며 로컬 총 304,916ms였다. 통화·분석 변경의 CI 영향 범위에도 기존 진행 통화 suite를 추가했다.

새 migration·환경변수·프론트/AI 변경은 없다. 운영 배포·운영 DB 직접 정정·과거 PBX 수신/녹취 복원은 하지 않았다. 실제 서버에는 이 수정이 포함된 앱 배포가 필요하다.
