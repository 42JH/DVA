# 통화 고객 연결

새 앱 실행 전에 `040-call-customer-reference.sql`을 적용한다. `call_sessions.customer_seq`는 nullable인 고객 번호이며 물리 FK를 두지 않는다. 미등록 고객도 통화·분석·발화·미답변을 저장할 수 있다. 프론트·AI 요청과 응답 형식은 바뀌지 않는다.

- 통화를 처음 저장할 때 발신번호로 확인한 고객 번호를 함께 저장한다. 고객이 없으면 null이다.
- 통화 중 등록된 고객은 기존 고객 context 요청에 call을 포함하거나 최종 주문 결과를 받을 때 같은 트랜잭션으로 연결한다. 주문 없는 `NO_ORDER` 결과도 포함한다. 고객 등록 요청만으로 과거 통화를 일괄 연결하지 않는다.
- 한 번 연결한 고객 번호는 재전송으로 덮어쓰지 않는다. 고객 이름은 현재 고객 정보에서 읽지만, 전화번호가 바뀌어도 고객 연결은 유지한다.
- 통화·미답변 조회는 주문 고객을 우선하고, 주문 고객이 없으면 통화에 저장한 고객 번호를 사용한다. 미등록 통화에 나중에 같은 번호로 등록한 다른 고객을 조회 시점에 연결하지 않는다.
- `caller_phone_number`는 통화 당시 발신번호다. 전화번호 검색과 PBX 녹취 매칭에는 계속 사용한다.

기존 통화는 migration에서 주문 고객을 우선 복원하고, 주문이 없으면 적용 시점에 발신번호와 일치하는 고객을 연결한다. 이미 전화번호가 변경되거나 재사용된 과거 문의의 실제 고객은 현재 데이터만으로 복원할 수 없다. 적용 전 해당 데이터는 별도 확인해야 한다.

migration은 컬럼 추가와 기존 행 보완을 같은 배포 트랜잭션에서 실행한다. 실제 서버 적용·배포는 별도이며, 앱만 이전 버전으로 복구할 때 추가 컬럼은 유지할 수 있다.
